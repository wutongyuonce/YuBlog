# 旅行

`/trips/` 是一张全屏地图，记录作者的旅行计划和已经走完的行程。地图铺满整页，右侧浮起旅程面板（768px 以下改为底部面板），没有站点顶栏和页脚；左上角的作者胶囊回到博客首页。入口在顶栏「更多」菜单。

行程在圆周旅迹里规划，由导入脚本转换成站内的中立数据后提交到仓库；页面只读这份数据，不在访问时请求圆周旅迹。

## 页面行为

**总览。** 面板顶部写「N 段旅程 · X 天 · Y 个地点 · 约 Z 公里」，标题「旅行」旁注明行程数据采集自圆周旅迹并做了适配，不逐条标出来源。旅程按开始日期倒序，按年份分组，每张卡片依次是封面拼图、标题、日期范围、「天数 · 地点数 · 约 N 公里」，以及「计划」或「记录」标记。地图同时画出全部旅程的路线和停靠点：颜色按开始年份区分，停靠点在缩小时聚合成带数字的圆；左下角图例列出年份和路线样式。

**状态。** 以 `Asia/Shanghai` 的当天为准：结束日已过的旅程标为「记录」，否则为「计划」。构建时先按构建日期渲染一次，浏览器再按访问当天重算，所以页面不需要因为日期变化而重新部署。

**选中旅程。** 点击卡片、地图上的路线或停靠点，会打开这段旅程的详情，地址变为 `/trips/#<id>`，可以分享，浏览器的后退会回到总览。详情包括：

- 封面拼图和三个数字：天数、地点数、公里数。
- 「回放行程」按钮。
- 按天列出的停靠点：序号、分类图标、名称、时间段、备注和照片。

地图会缩放到这段旅程，其它路线变淡，停靠点改为带序号的圆点。指针停在某个停靠点的条目上时，地图会高亮对应的点；点击条目则把地图移过去。照片点击后用对话框放大，可以前后翻看同一段旅程的照片。

**回放。** 回放时面板收起，底部卡片依次显示天次、停靠点序号、名称、时间、备注和第一张照片。地图沿路线逐段画线，一个标记沿线前进，镜头跟随；到站后停留片刻再出发。可以暂停、继续或退出，退出后回到详情。系统开启「减少动态效果」时不播放线条和镜头动画，只逐站切换。

**降级。** 没有 JavaScript 时，面板以静态列表呈现，卡片通过 `#<id>` 锚点用 `:target` 展开详情。没有配置 Mapbox token，或者地图加载失败时，地图区域显示原因，列表、详情和照片照常可用，回放按钮停用。

## 数据

每段旅程放一个目录 `src/data/trips/<id>/`，里面是 `trip.json` 和它引用的图片。`id` 是 URL 片段，发布后不要改。字段契约以 `src/content/schema.ts` 的 `tripSchema` 为准：

```jsonc
{
  "title": "重庆市3日游",
  "start": "2026-11-06",
  "end": "2026-11-08",
  "cover": ["./cover.jpg"],          // 封面候选，按优先级排列，可为空
  "days": [
    {
      "date": "2026-11-06",
      "summary": "SPA·全季·绿心·西南", // 可选
      "stops": [
        {
          "name": "绿心公园",
          "category": "景点",           // 可选，显示用分类名
          "emoji": "⛲️",               // 可选
          "address": "…",              // 可选
          "coordinates": [106.53, 29.6], // WGS84，[经度, 纬度]
          "time": { "start": "11:00", "end": "16:00" }, // 可选，任一端可省
          "note": "…",                 // 可选
          "photos": ["./s01-1.jpg"],
          "route": {                   // 到下一站，最后一站没有
            "mode": "drive",           // drive / walk / straight
            "distance": 6200,          // 米
            "duration": 900,           // 秒，straight 时没有
            "path": [[106.53, 29.6], …]
          }
        }
      ]
    }
  ]
}
```

- **中立性。** 数据里不保存圆周旅迹的行程 ID、分享链接、用户 ID、昵称或头像。
- **日期。** `start` 是第一天，`end` 是最后一天；`days` 按日期递增且不重复，没有安排的日子保留空的 `stops`。
- **坐标。** 统一为 WGS84，供 Mapbox 直接使用；GCJ-02 的转换只在导入时做一次。
- **路线。** `route` 属于出发的那一站，相邻两天之间也连起来，地图上就是一条连续的线。路径保留 5 位小数（约 1 米），并做约 5 米容差的抽稀。`straight` 表示路线服务没有结果，按两点直线计算距离，不提供时长。
- **封面拼图。** 最多取三张，候选依次是：`cover`，各站 `photos`（去重），兜底地点图。三类都没有时，显示带标题首字和路线轮廓的文字占位。
- **图片。** 导入时把长边缩到 1600px 以内，转成质量 82 的 JPEG；构建时由 Astro 再生成 WebP 的多种尺寸。图片不从外站热链。

页面的统计和展示规则集中在 `src/utils/trips.js`，包括：状态、天数、地点数、总里程、年份配色、日期文案、拼图取图。构建期页面和浏览器的状态重算都调用它，不在别处重复推断。

## 导入

```bash
pnpm trips:import '<圆周旅迹分享链接或行程 ID>' [--id <站内 id>]
```

1. `src/utils/pitravel.mjs` 是圆周旅迹适配器，也是唯一了解其数据形状的模块。它从链接中取出行程 ID，请求公开接口 `GET https://www.pitravel.cn/api/slytherin/v1/web/journey/detail?journey_id=<ID>`，再按下面的规则转换：
   - `code !== 0`、行程不存在或不公开时，报错退出。
   - 名称、日期、每天的概要和停靠点按原顺序映射。日期取每天的 `timestamp`，按上海时区换算；`day_index` 为 -1 的「待计划」不导入。
   - 坐标从 GCJ-02 转为 WGS84；分类取 `category[0].display_name`，图标取 `category[0].icon`。
   - 交通方式取 `route_transportation_type`：0 为驾车，1 为步行，其余按直线处理。
   - 只读取上面列出的字段，用户资料不会被读出。
2. `src/utils/trip-routes.mjs` 按交通方式向公共 Valhalla（`valhalla1.openstreetmap.de`，`auto`／`pedestrian`）逐段请求路线，每次请求 15 秒超时、不重试。失败或没有结果的那一段降级为 `straight` 并给出警告，不会让整次导入失败。
3. `scripts/import-trip.mjs` 负责落盘：
   - 下载封面和照片，并缩放、转码。
   - 本站已有圆周封面或照片时，不保存兜底地点图；否则最多保存三张地点图，作为封面候选。
   - 单张图片下载失败时跳过并警告。
   - 先在临时目录写好全部文件，再整体替换 `src/data/trips/<id>/`，导入中途失败不会留下半份数据。
4. `--id` 省略时取第一天日期，例如 `2026-11-06`。重新导入同一段旅程时传入原来的 `id`，就会覆盖原目录。脚本不保存来源链接，所以由调用方（内容发布 skill）通过标题和日期确认是同一段旅程。

圆周旅迹的接口和 Valhalla 都是非官方或公益的公共服务，可能变化、限流或不可用。它们只在导入时访问，影响不到已经提交的数据和线上页面。

## 地图

- **底图与加载。** 地图使用 Mapbox GL JS，底图在深浅主题下分别为 `dark-v11`／`light-v11`，中文标注（`language: 'zh-Hans'`），中国视角边界（`worldview: 'CN'`）。只在本页按需加载，不进入全站脚本。
- **token。** token 从构建时的公开环境变量 `PUBLIC_MAPBOX_TOKEN` 读取。它会出现在页面里，需要在 Mapbox 控制台限制可用的 URL。
- **几何数据。** 由静态端点 `/trips/map.json` 提供：每段旅程的 id、年份颜色、各站坐标与序号，以及逐段路径。页面 HTML 只放文字和图片。
- **主题与换页。** 主题切换时换底图并重新添加图层。ClientRouter 离开本页时销毁地图、取消动画和监听。

| 规则 | 权威 |
| --- | --- |
| 中立数据字段与校验 | `src/content/schema.ts` 的 `tripSchema`，集合定义在 `src/content.config.ts` |
| 圆周旅迹的形状、坐标系和交通方式映射 | `src/utils/pitravel.mjs` |
| 路线请求、抽稀和直线降级 | `src/utils/trip-routes.mjs` |
| 下载、缩放和原子落盘 | `scripts/import-trip.mjs` |
| 状态、统计、配色、日期文案和拼图取图 | `src/utils/trips.js` |
| 集合读取、排序与图片解析 | `src/utils/trip-entries.ts` |
| 地图、图层、选中与主题 | `src/utils/trip-map.ts` |
| 回放的时间线与镜头 | `src/utils/trip-replay.ts` |
| 面板、地址片段、照片对话框和页面生命周期 | `src/pages/trips/index.astro` 的页面脚本 |

## 非目标

- 不在站内编辑行程、协作或同步圆周旅迹，也不在运行时请求圆周旅迹。
- 不从照片自动发现旅程，不提供日历视图、截图录屏、3D 车模、天气、音乐或车辆数据。
- 不保存来源链接，也不区分「计划」和「记录」两种数据；状态只由日期决定。

## 验证

```bash
node --test test/pitravel.test.mjs test/trip-routes.test.mjs test/trips.test.mjs test/content-schema.test.mjs
```

- `pitravel.test.mjs`：链接解析、坐标转换、待计划日的排除、字段映射，以及不导出用户资料。
- `trip-routes.test.mjs`：Valhalla 解码与抽稀、失败时降级为直线。
- `trips.test.mjs`：状态的日期边界、统计、配色和拼图兜底。
- `content-schema.test.mjs`：`tripSchema` 的边界。

`test:built-restructure` 检查 `/trips/` 的结构、无 JS 列表、`map.json` 形状和「更多」菜单入口。

浏览器另外需要核实：

- 深浅主题，以及 1440／390／320px 三种宽度。
- 选中、后退和回放（含减少动态效果）。
- 照片对话框。
- 无 token 和地图加载失败时的降级。
