## 1. 路由与使用场景

| 页面 | 路由 | 职责 |
| --- | --- | --- |
| 首页 | `/` | 作者、RSS、六个社交入口、名言、写作热力、时间进度、最近五篇文稿、屏幕时间、近期书影游和 Last.fm 听歌排行 |
| 文稿 | `/blogs/` | 全量文章列表、分类／标签筛选、每页八篇 |
| 分类 | `/blogs/#技术`、`#思考`、`#旅行`（名称经 URL 编码） | 同一文稿页的原值精确筛选状态，非独立静态页面；旧 `#tech`、`#thought`、`#diary` 仅作 URL 兼容别名 |
| 标签 | `/tags/` | 标签目录、排序、多选 AND 筛选；无选择时不显示文章列表 |
| 归档 | `/archives/` | 单条时间线，按年组织，分类徽标辅助识别 |
| 拾趣 | `/interests/` | 按内容集合和 `order` 自动生成分类入口 |
| 拾趣子页 | `/interests/<id>/` | 对应分类文件的内容，标题不带“拾趣-”前缀 |
| 项目 | `/projects/` | 页头和按 JSON 分类的项目卡片 |
| 关于 | `/about/` | 页头及作者介绍；仅维护 `about.md`，无子页切换 |
| 友链 | `/friends/` | 推荐、双向两组卡片及交换说明 |
| 正文 | `/blogs/<slug>/` | 独立标题、可选封面、正文和目录 |
| 订阅 | `/rss.xml` | 开发和生产均只含已发布文稿的完整正文，不包含页面壳或交互 |

## 2. 用户场景与产品规则

鼠标／触屏操作及其弹窗焦点恢复不显示额外的焦点外框；Tab、方向键等键盘操作恢复可见焦点提示。焦点本身、原有悬停反馈与输入能力保持，站内页面交换保留当前输入方式，无脚本沿用浏览器焦点提示。图片大图与画布展开窗口共用无圆形底色的居中叉号关闭按钮；画布关闭叉号固定白色，图片大图关闭叉号随主题。浏览器回归见 `scripts/verify-media-focus.mjs`。

### 首页认识作者，再进入文稿

首页先显示作者名片，写作热力下方显示三列细时间进度，其后为近期笔墨，再显示屏幕时间。屏幕时间呈现最近同步当天的活跃时长和七天柱状图，详细口径与失败语义见 [ActivityWatch 屏幕时间](./screen-time.md)。头像与作者信息作为一组居中；头像右侧的梧桐雨与 INTJ 上下排列、左边缘对齐，INTJ 在名字下方，字号为 13px；「订阅 RSS」始终在同一行右侧（含 600px 及以下），窄屏缩小头像与标题字号，按钮标签不换行。下方依次为一行居中的六个社交图标和独立一行居中的斜体名言「我与我周旋久，宁做我」。图标横向间距为桌面 15px／窄屏 9px，名言较长时在版心内自动换行，不再显示全站文章、字数或写作天数。社交入口保留名称供读屏和悬停提示，身份由 `AUTHOR_LINKS` 维护，包含 GitHub、X、Instagram、Bilibili、小红书与邮箱。

悬停头像或作者名所在的身份链接，或通过键盘聚焦该链接时，作者名使用当前强调色，头像同步显示 35% 透明度的同色光晕；光晕随配色及亮暗主题变化。默认使用 180ms 淡入淡出，减少动态效果时直接切换。

名片与近期笔墨之间是写作热力。标题「写作热力」与「近期笔墨」左对齐，年份在同一行右侧以下拉选择；只有一年时只显示年份。格子按上海时区的自然年排列，周一为一周之始，覆盖 1 月至 12 月。年外补齐日不着色、不计数。每年摘要按同一上海自然年显示篇数、字数和有文章的天数；字数是该年已发布文章的可读字数，满一万用「万」，缺字数时构建失败，不显示 0。只统计已发布文章，同一天多篇合并；强度为无文章、1 篇、2 篇、3 篇、4 篇及以上。颜色用强调色混入背景，浅色白底、深色黑底与当前点缀色。年份从第一篇所在年到「最晚发文年与当前上海自然年二者较晚者」，当前年无文也会列入；不补博客开始前的空年。默认选中当前年（若在列表内），否则选最近有文章的年份。没有已发布文章时不渲染。单篇格子链到文章或重定向地址；多篇格子在启用脚本后展开各篇链接。空日不进入 Tab 顺序。年份切换为标题旁的自定义下拉：点击后列表在触发器下方展开，不用系统选择器；靠隐藏单选与 CSS 显示对应年面板，无脚本仍可展开并切换；脚本负责 Escape、点击外部关闭，以及选中后更新触发器文案。提示层在视口内限高并可滚动，不限制当天文章数量；键盘焦点留在提示层时不因指针离开而关闭，提示层内部滚动不关闭；Escape 返回触发格子，页面交换清理定时器和监听。窄屏保持格子尺寸，在版心内横向滚动；放得下时格子组居中。

首页最近五篇只包含已发布文章；每项有标题、分类与日期，标题在悬停和键盘焦点时出现下划线。全部文稿进入 `/blogs/`。首页带 `?page=`、`?category=`、`?tag=` 的兼容书签在启用脚本时解析为文稿页地址，保留参数和 hash；无脚本时首页仍可阅读。部署必须保留 `/blogs/` 的独立列表页面，不将 `/blogs` 或 `/blogs/` 重定向回首页；分类 hash 随同文稿 URL 保留，Vercel 使用 Astro 构建路由。

近期笔墨下方先显示屏幕时间（见 [ActivityWatch 屏幕时间](./screen-time.md)），其下为近期书影游，内容只来自 `src/content/interests/recent.md`，不生成拾趣子页或菜单项。无外框或专用内容宽度，继承首页版心；标题层级、锚点和卡片均使用共享 Markdown 样式。近期条目用竖版横滑栏，封面、标题与顺序沿用原内容，小字使用可适度精简的原介绍／评论；不显示原评分或类别角标。所有条目保持一排，后续可横滚；不启用 `scroll="auto"`，仅手动横滑。标题右侧「全部拾趣」进入拾趣入口；标题 `href` 指向对应作品 Wiki，而非本站拾趣分类。

近期书影游下方是「最近在听 TOP10」：过去七天 TOP 10 歌曲保持一排横滑，封面使用专辑图，歌名为大字、小字用 `歌手 - 专辑名`；超出容器时沿用正文卡片的头尾循环及暂停／回退规则，封面可点击或键盘打开现有查看器查看远程原尺寸图。辅助统计展示七天听歌次数、累计记录数、七天最常听歌手，另注明数据时间；标题右侧「Last.fm ↗」进入个人主页。数据在访问时由 `/api/lastfm` 取得并缓存 30 分钟，构建产物不含听歌数据、也不请求 Last.fm API；接口失败时区块显示失败说明，专辑资料缺失使用真实空状态，无脚本时保留骨架与说明。完整失败、资源和验收契约见 [Last.fm 接口与展示](./listening.md)。

### 分类、标签和分页

博客分类以 frontmatter 的 `category` 原值为准，不合并任何别名，不归到兜底类别。首页、列表与归档直接读取 `data.category`，菜单也按原值展示、计数与精确筛选；分类名称与篇数由当前已发布内容生成，不维护固定名单或数量快照。

重新构建后，文稿菜单按已发布文章的原始分类生成入口，按篇数降序，同数按名称的 `zh-Hans-CN` 排序；不保留固定分组或空分类。分类使用 `/blogs/#旅行` 这样的名称编码 URL 片段（hash），旧 `?category=` 始终按原值精确筛选。分类 hash 及兼容 query 均可与标签、分页组合；畸形编码忽略 hash 后按 query 处理，不抛出异常。启用脚本后旧 query 规范为等价片段地址，保留标签、页码及其他参数。旧 `#tech`、`#thought`、`#diary` 仅作为 URL 兼容别名，分别定位原值“技术”“思考”“日记”，不合并“技术向”等名称；英文原值 `tech`、`thought`、`diary` 使用 `#category=tech` 等形式逃逸，仍为精确筛选。

文稿和标签筛选结果的文章标题使用宋体加粗（700），共用 `ListItem`；文稿列表标题字号为 18px，描述与元信息使用普通字体。文稿先对全量数据筛选，再分页，每页八篇。类别 hash 优先于兼容的 `?category=`；重复标签归一化、多选为 AND。修改筛选回第一页，分页保留筛选，越界页回到有效页，前进／后退恢复 URL 状态。首屏不先展示不匹配的第一页；禁用脚本时文稿展示全量文章及说明，标签页保留标签目录和启用脚本提示。

文章标题下、归档标题下和文稿列表卡片的标签以 `#标签名` 逐个展示，标签之间留空隙，不用 ` / ` 拼接。每个标签链接到 `/tags/?tag=`，只选中该标签。标签名中的 `/`、`#` 或其他字符不是分隔符；展示前缀 `#` 不参与匹配，查询串编码后仍精确选中原值。空白标签不生成链接，重复标签只保留一个。无脚本时链接仍打开标签页，选中与列表筛选沿用既有脚本。

文章分类和搜索状态以当前 frontmatter 为准，不要求保留具体文章或占位内容。`search: false` 只控制搜索；未标为草稿的文章仍进入生产列表、归档和 RSS。

### 顶栏和下拉菜单

品牌“梧桐雨の博客”是首页入口；其余按钮为文稿、标签、归档、拾趣、项目、关于、更多，右侧保留本仓库 GitHub、搜索、配色选择和主题开关。顶栏文字统一使用宋体。品牌为桌面 16px、601–799px 为 14.72px、600px 及以下为 14.4px，行高 1，容器与菜单保持中心对齐。首页品牌为当前强调色并轻微加厚，字宽不因选中而变化；其他当前项浅色黑底白字、深色白底黑字，未选中项悬停使用灰底。

文章及文稿分类属于文稿，拾趣子页属于拾趣。导航配置的尾斜杠不改变菜单或父级选中；服务端与客户端从 `nav-path.js` 读取同一规则，支持站点 base。滑块只使用顶层按钮坐标，同一父级内切换保持原位；文章入口无论来自标签、归档、首页、列表或菜单，都在导航准备阶段定位文稿。页面交换前后不重建滑块，不从零位置补播。最新导航目标拥有预览，旧请求取消不得撤回新目标；导航失败或被取消时恢复已加载页面的状态。`aria-current` 描述已加载页面，目标预览使用独立属性。

顶部文稿分类菜单只读取 `getPublishedBlogPosts` 集合：`draft` 不参与分类入口、计数或最近文章，这是明确的设计边界；仅含草稿的分类不出现，已发布集合为空时类别为空，仅保留“查看全部文稿”链接。开发网页列表与正文的草稿预览不属于此边界，行为不变。菜单左列按篇数降序、同数按名称的 `zh-Hans-CN` 排序，固定间距自上而下排列，不随右列拉高；右列最多四篇当前类别的最近已发布文章，保持共享发布日期顺序不变。面板高度取左右列较高者；分类较多时面板在视口内滚动，长名称换行；穿过行间空隙或右侧沟槽保留当前类别，不回退第一项。文章标题悬停／焦点有下划线，底部查看全部文稿行保持紧凑。拾趣菜单读取集合元数据，新分类随 Markdown 自动加入；标题、说明和顺序来自内容，图标按 `INTEREST_ICONS` 配置显示，未配置时显示纯文字、不留图标占位。拾趣和更多下拉框最大宽度 200px，并受导航容器宽度限制。更多菜单读取 `config.ts` 的 `MORE_LINKS`，友链指向 `/friends/`，友链页选中更多；相册指向独立部署的 `https://photos.wutongyu.site/`；访问统计指向 `https://cloud.umami.is/share/Xna7YqwEWNnoAv2x` 的公开看板，无需登录。两个外链均显示 ↗，以新标签页打开并带 `noopener noreferrer`。

桌面 hover 或键盘焦点展开，触屏首次点名称展开、再次点进入入口页；ArrowDown／空格进入菜单，Enter 正常导航，Escape（包括仅鼠标悬停、焦点在菜单外时）和外部点击关闭。无脚本仍可通过 hover／focus 使用链接。

顶部 80px 内导航保持可见；同方向累计滚动 18px 后下滑隐藏、上滑显示。键盘焦点、打开的菜单或搜索会保持导航可见；页面切换恢复可见。减少动态效果偏好下关闭相关过渡。

### 拾趣和关于

拾趣入口与全部分类子页均使用点状背景。分类来自 `src/content/interests/` 顶层的 `.md` / `.mdx` 文件，排除 `recent.md`，不限定分类 ID 或数量。

每个分类必须提供非空 `title`、`description` 和非负整数 `order`；入口与菜单按 `order` 升序展示，子页路径为 `/interests/<文件名去掉扩展名>/`。新增分类重新构建后自动生成页面、入口和菜单，无需修改路由或导航数组。图标唯一配置为 `src/config.ts` 的 `INTEREST_ICONS`，键为分类 ID，仅查询映射自身的键，不读取原型链；未配置时菜单只显示文字，不渲染图标容器或占位；图标值自动加入 UnoCSS safelist。拾趣没有博客的 `draft` 过滤，新增文件随下一次构建发布。

入口页只展示分类列表；首页近期书影游只来自 `recent.md`，该文件不生成分类子页或菜单项。分类子页复用文章目录，按全局配置收录正文标题；没有符合级别的标题时不显示目录。当前分类包括设备、动漫、电影、电视剧、游戏、书、Kpop、软件；这是内容现状，不是允许列表。各分类说明以内容元数据为准。电影、电视剧、动漫、游戏的条目使用默认 `:::card`，按容器宽度自动分列，当前版心最多两列。横卡的可选评分、日期、评论限高，以及竖卡／方卡的完整规则见 [正文卡片](./content.md#cards)。拾趣正文以三级标题分组，需要细分时使用四级标题；书页使用竖卡，按类型以三级标题分类，每类独立一排横滑栏，数量少或边界不清的类别可合并；组内保留原条目顺序，封面对应书名及作者，作者作为小字，不显示评分；当前桌面版心大约显示四本半并可继续横滑。关于页只渲染 `about.md`，复用正文目录，无正文标题时隐藏，没有子页切换。

博客、拾趣、首页近期书影游与关于正文在 `prose.css` 共用标题字号和间距：h1 为 34px、h2 为 25.6px、h3 为 19px、h4–h6 为 16px（根字号 16px 时）。Markdown 的一至六个 `#` 按原样生成 h1–h6，不将文中最高级标题提升为 h1；标题文字后的单个 `#` 是 `rehype-autolink-headings` 追加的锚点链接（视觉在标题右侧、带小间距，不向左悬出），与层级无关。页面顶部的宋体标题独立渲染，不属于正文 Markdown。

### 归档和友链

项目按 JSON 的 `category` 原值分组，不设分类允许名单；`constructor`、`__proto__` 等合法名称也必须正常分组，每条项目只呈现一次。项目与友链卡片网格固定两列，宽度随版心伸缩，窄屏不切换为单列。

归档按共享发布日期顺序排成一条时间线，年份为宋体 22px，日期为宋体，文章标题为宋体常规字重（400）、字号 14.72px；日期列右对齐并靠近时间线，年份在同一列展示。日期、标记与标题首行共用 24px 行高。标题下的标签使用同一 `#标签名` 单标签链接，换行不改变所选标签。所有分类的小点均为灰色，悬停／焦点均为当前强调色短竖线；标题右侧的圆角徽标包含分类文字，不能仅靠颜色区分。归档分类从 `src/data/blog-category-colors.json` 的 16 色预设池中领取配色，`assignments` 保存分类原值到配色 ID 的映射；不同分类不复用同一颜色值。开发访问归档或构建归档时，新分类领取未使用颜色并自动写入记录；开发归档中展示的草稿分类也会领取颜色。新增、删除分类或调整文章顺序不改变已有分配，删除分类后保留占位，重新出现沿用原色。「技术」「思考」「日记」预先记录为蓝、暖红、青色，保留当前配色。预设颜色值不同，但不保证任意两种都能肉眼明显区分。配色池耗尽时构建失败，须补充不同色相的新预设后重试；发布新分类时配色记录与文章一起提交。长分类徽标限制宽度并换行，不挤出手机页面。

友链 category 仅允许“推荐”或“双向”，每条友链的类别以当前数据为准；不设必须保留或禁止添加的站点名单。组内按 `order`／名称排序，两组用较小宋体标题及说明分隔，“交换友链”使用普通无衬线字体加粗（700）。申请区在 920px 以上左右等宽并等高，更窄时上下排列；规则为“先友后链”和“使用 https 协议”。卡片悬停／键盘焦点加强边框和名称颜色，头像放大 10%，头像与卡片外边框显示 35% 主题强调色柔光，不加实色光圈；离开后以 180ms 过渡复原，减少动态偏好下取消过渡。黑夜卡片背景为纯黑，深浅主题可读。

### 文稿上下篇与随便逛逛

读者在读完一篇文稿后，需要低摩擦地进入相邻文稿或任意另一篇；在文稿列表任意分页上也能一键「随便逛逛」。交互保持 YuBlog 稀疏、轻量的壳层气质，不引入喧闹按钮或额外分页状态。

#### P1：详情页导航行

- 位置：正文之后、评论区之前（`after-content` 槽，排在 Giscus 前）。
- 文案：`← 上一篇`｜`随便逛逛～`｜`下一篇 →`。
- 边界：有序列表中**最新**一篇（数组下标 0）不显示「下一篇」；**最旧**一篇不显示「上一篇」；中间三枚齐全。仅一篇已发布（或当前可见）文稿时，「随便逛逛」亦不显示。

#### P2：顺序与邻接语义

与文稿列表、`getSortedPosts` 完全一致：

1. `pubDate` 降序（新 → 旧）
2. 同日按 `id.localeCompare` 升序

中文博客常见约定（本站采用）：

| 标签 | 含义 | 在降序数组中的位置 |
| --- | --- | --- |
| **上一篇** | 更旧的一篇 | 当前下标 + 1 |
| **下一篇** | 更新的一篇 | 当前下标 − 1 |

#### P3：随便逛逛

- 详情页：从**当前可见集合**中随机一篇，**排除当前**。
- 列表页：从同一集合中随机任意一篇。
- 集合与详情／列表一致：生产环境排除草稿；开发预览与 `getFilteredPosts` 对齐（可含草稿）。
- 实现：服务端写出候选 URL 列表与无脚本回退 `href`；一小段客户端脚本在 `astro:page-load` 时从候选中重写 `href`。兼容 ClientRouter／View Transitions；无脚本时回退链仍可用。

#### P4：列表页顶行与首页

- 文稿页（`ListView`，含标签页复用）在列表 UI **顶部**增加单独一行「随便逛逛」。
- **不参与分页**：不论当前页码或筛选，该行始终渲染在分页列表之上（位于分类头／筛选区之后、`[data-post-list]` 之前，且在 `[data-list-panel]` 内时随面板显隐；无标签选中时标签页面板隐藏则该行一并隐藏，避免空态噪音）。主文稿列表始终可见。
- 首页「近期笔墨」标题行右侧增加同一套「随便逛逛～」（与「全部文稿」并排）；候选为已发布文稿（`getPublishedBlogPosts`）。

#### P5：UI

- **无边框按钮**：上一篇／随便逛逛／下一篇与正文链接一致——底边 `1px` 浅灰下划线，悬停改为强调色（同 `markdown.css` 的 `.prose a`），无描边胶囊、无填充底。
- **装饰符**：上一篇前缀 `←`，下一篇后缀 `→`，箭头使用浅灰色，与文字留出 `0.4em` 间距；随便逛逛仅右侧装饰波浪 `随便逛逛～`（`aria-hidden`），详情／列表／首页一致。
- 邻接链接提供 `title`（篇名）便于悬停预览。

#### 上下篇验收

- 降序夹具上：最新无下一篇、最旧无上一篇、中间双向正确；同日 `id` 并列次序与 `getSortedPosts` 一致。
- `pickRandomOther` 在排除当前后从不返回当前；候选为空时返回 `null`。
- 详情页：正文 → 上下篇行 → 评论。
- 列表页：顶行不随分页消失；换页后仍在。
- 首页近期笔墨标题右侧有「随便逛逛～」，与全部文稿并排。
- 无 JS：随便逛逛仍有可点的回退链接；有 JS：每次 `astro:page-load` 可换候选。
- `pnpm` 相关 test／format／lint／check 子集通过。

#### 上下篇范围

- 不按分类／标签限定随机范围。
- 不做「阅读历史」加权随机。
- 不改 RSS、归档时间线结构；首页仅在「近期笔墨」标题行增加随便逛逛，不改时间线条目。

### 有封面和无封面文章

长行内代码可断行，原生 `pre/code` 保留换行与缩进；宽块级公式在自身容器横滚，内容可访问，不带动页面横移。公式输入语法以 [publisher skill 的作者契约](../../blog-content-publisher-skill/SKILL.md#公式与代码标记) 为准。

文章始终保留一个独立宋体 h1 及日期／阅读时长／标签信息。标题下的标签为 `#标签名` 链接，指向标签页并只选中该标签；名字里的 `/` 或 `#` 不拆开标签。有封面时在其下渲染图片卡片：重复标题用段落，描述取 `description`、缺失时取 `subtitle`，作者行只含 40px 头像、梧桐雨与日期。封面白字和深色渐变遮罩适配两种主题。无封面时保持标题和正文结构，不构造假封面。

文章、拾趣子页和关于页共用目录，默认收录正文 h1–h4；页面顶部标题不参与。目录第一层不绑定 h1：正文从 h2 或 h3 开始时，该级标题直接成为第一层，其下按相对层级嵌套；正文 HTML 标题级别保持原样。目录按配置的标题级别过滤，仅在存在可导航条目时挂载桌面和移动端目录；两端消费同一棵目录树，并按顺序与真实层级嵌套：h2 → h3 → h4 的 h4 属于已有 h3，仅在实际缺失中间层级时补空项，不制造重复父级。

桌面 1200px 及以上目录常驻、无顶部 TOC 按钮；小屏保留浮动目录入口。目录在正文边缘和视口外边距之间的留白中线基础上向外移 16px，最大宽度 208px，宽度为侧边留白减 48px 与该上限中的较小值，靠正文一侧至少保留 40px，外侧至少保留 8px（另有视口外边距）；中心比视口中线高 32px；高度不超过 `min(50vh, 28rem)`，长目录在内部滚动，当前项移入可视范围。

目录点击与章节高亮共用阅读边缘：导航隐藏为 20px，显示为其顶部位置、实际高度再加 12px。点击前从共享模块维护的实际累计滚动状态预测显隐（预测不修改状态），让原生 fragment 滚动直接使用目标距离，不进行第二次补滚。滚动、字体／图片布局变化、缩放和导航显隐重新同步；到页面真正底部最后章节胜出。保留正常 URL hash 和历史返回语义；离开文章后清理监听、观察器及临时定位变量。无脚本时保留可见导航所需的静态间距。

### 全站点缀配色选择

首次访问默认原粉色，浅色主强调色为 `#ad526c`，深色主强调色为 `#e7a1b5`。顶栏配色入口位于主题按钮左侧，桌面和手机均保留，工具顺序为 GitHub、搜索、配色、亮暗主题。按钮显示调色盘与当前色点，点击展开五行选择面板：原粉色、灰紫、深紫、雾蓝、鼠尾草绿。名称和选中标记共同表达状态，不仅依靠色点。选择立即更新当前整页、关闭面板并恢复按钮焦点；重复选择当前配色安全且不改变阅读状态。

配色只调整全站样式控制的点缀：品牌、链接、强调、按钮／标签的点缀态、目录标记、热力图、搜索高亮、友链柔光、正文列表及引用等。原有黑白基底、排版和亮暗主题行为保持；内容图片、代码语法高亮、归档分类徽标、提示框的独立语义色、卡片独立绿色标题／日期值与金色评分不随配色切换。每套预设的浅色与深色强调色都不同：浅色模式使用主色，深色模式使用同色相、更亮的强调色，保持黑底可读和热力层次。选择面板的色点固定显示浅色主色，不随亮暗主题改变。灰紫浅色 `#665477`、深色 `#d0adf2`；深紫浅色 `#3a1b74`、深色 `#a987e8`；原粉色浅色 `#ad526c`、深色 `#e7a1b5`。雾蓝浅色 `#476d89`、深色 `#7fafd2`；鼠尾草绿浅色 `#52735c`、深色 `#7fd298`。这两套深色保持各自色相，不混成近灰。柔和色用于次级点缀，深色下不比强调色更暗。切换不刷新、不跳转、不改变滚动位置、目录、筛选、页码或搜索输入。

选择器可通过鼠标、触屏或键盘操作。Enter／空格打开并进入当前项，方向键移动选项，Home／End 到首尾，Enter／空格确认；Escape 关闭并返回按钮，点击外部或焦点离开关闭。展开时导航保持可见；面板受视口宽高约束，320px 手机不产生页面横向溢出。配色更新不增加非必要动画，沿用减少动态效果偏好。

有效选择在当前浏览器保存，与亮暗主题使用独立偏好；硬刷新首屏和 ClientRouter 页面交换前恢复，避免默认色闪现。缺失／非法保存值回退原粉色，存储不可用不妨碍当次选择，但后续重新加载允许回到默认。最后一次选择生效；不提供跨设备同步、任意颜色编辑或多标签页实时同步。无 JavaScript 时使用默认原粉色并隐藏无法工作的选择器，内容仍可阅读。

### 在正文下评论与申请友链

读者在每篇博客正文与上下篇／随便逛逛之后、友链页列表与交换说明之后、每个拾趣分类子页正文之后使用 Giscus 留言；拾趣入口、首页、列表、标签、归档、项目和关于不显示评论。新增拾趣分类自动沿用子页评论，不维护固定分类列表。友链申请使用现有模板中的站名、简介、网址、头像，留言供作者审核后人工维护友链数据，保留 PR 申请方式。

评论区与正文、博客整体使用同一版心宽度并居中，随桌面与手机视口收窄；文章页顺序为正文 → 上下篇／随便逛逛 → 评论区，评论 iframe 不得延伸到目录区域或撑宽页面。

评论存入公开仓库的 GitHub Discussions，访客可以阅读，发表与回应需要 GitHub OAuth 登录。每个页面使用规范化、带尾斜杠的 pathname 作为独立关联键，忽略域名、query 和 hash；相似路径严格匹配，不共享评论。中文路径使用 URL 编码形式。站点 base 是路径的一部分；修改 slug 或 base 前需处理旧讨论的关联，本站不自动迁移。

空闲时允许预取同域评论模块并预连接 giscus.app；接近评论区（进入视口外 640px 范围）时才挂载 iframe 并加载 GitHub，短页可能首屏已在此范围内，无需滚动即加载；OAuth 回调立即初始化以保存登录结果。评论初始配色及之后的切换都跟随博客实际明暗主题，切换不重建 iframe。ClientRouter 换页后使用新页面的关联键，旧组件停止观察主题与可见性，不后台轮询、不持有本站评论缓存。评论不属于作者正文，不进入全文 RSS 和 Pagefind 正文索引。

尚无留言不是失败：Giscus 在第一次评论或回应时创建 Discussion。模块下载失败时显示提示；第三方网络、仓库配置或登录错误由 Giscus 展示，本站始终保留 GitHub Discussions 入口。无 JavaScript 时正文、友链模板和该入口可用。评论依赖 GitHub／Giscus 的网络与权限，不提供匿名身份、离线评论、自建审核后台、自动添加友链或独立限流机制。

| 图片与媒体 | 封面／正文图片由 Astro 生成变体，分享图 1200px；`public/` 放站点资源和独立 HTML 演示，不手写内容图片构建 URL；本地视频／音频由 `astro-media-sync` 镜像到 `public/_media/`，正文用相对路径引用；HTML 演示目录和 iframe 用法见[正文与媒体](./content.md#local-html-demos) |
| 页脚 | 宋体显示版权、Astro 和“萌ICP备20269668号”；启用 Oneko 时另有「隐藏小猫」按钮（左侧装饰性 `🐾`）。横向外边距与正文共用 `--site-gutter`，不另写固定内边距。宽屏段间用次要字色 `·` 分隔，窄屏纵向堆叠并隐藏分隔符。作者名指向站点首页，Astro 指向 `https://astro.build`，备案指向 `https://icp.gov.moe/?keyword=20269668` 并在新标签页打开，带 `noopener noreferrer`。链接悬停或键盘焦点变为强调色 |
| 访问统计 | `Head.astro` 加载一份 Umami Cloud 脚本；页面不显示计数、徽章或页脚文案 |
| Oneko 像素猫 | 由 `FEATURES.oneko` 控制；默认托管 classic 皮肤，跟随光标／睡觉／气泡／记位置／季节帽，减少动态时隐藏；页脚提供「隐藏小猫」；顶栏为避让区。不自托管、不开声音与激光。详见 [Oneko 像素猫](./oneko.md) |
| 主题与焦点 | 颜色源于 `--c-bg`、`--c-text`、`--accent`；点缀规则与独立偏好见[主题配色](#appearance)，变量由 `accent-palette.js` 统一生成；站点声明的浏览器原生颜色方案与当前博客主题一致，不对自定义颜色自动暗化；首访跟随系统，有效保存值在刷新后恢复；系统模式发生变化时同步切换。非法保存值回退系统，存储不可用不妨碍当次显示和切换，但不保证跨导航／刷新保存。切换按钮、颜色方案和 canvas 背景同步；减少动效时保留静态背景，仍响应缩放和主题变化，不启动动画循环。提供深浅主题及可见键盘反馈，不依靠颜色表达类别 |

装饰背景在主体内部的独立层级中，位于主体底色之上、页面内容之下；即使外部样式把主体底色改为不透明，也不因此遮挡背景。背景仍相对视口固定，不拦截内容交互。外部暗化工具可以覆盖站点声明的配色，不保证其覆盖后的颜色仍与主题按钮一致。

## 4. 实现职责

页面只读取并呈现共享模块的结果；配置、集合、分类、分页、导航、主题、目录与评论的属主及调用接口见 [架构与模块边界](./architecture.md#ownership)。正文与订阅的更细职责分别见 [正文管线](./content.md#pipeline) 和 [RSS 设计](./distribution.md#rss-design)。

<a id="failures"></a>

## 5. 失败、并发和资源语义

正文组件的语法失败、图片资源、滚动锁与循环副本规则见 [正文与媒体](./content.md#verification)；RSS 的串行处理和失败规则见 [SEO 与全文订阅](./distribution.md#rss-design)。

- 静态内容在构建时验证。缺少作者介绍或无效 schema 明确报错；无文章／无匹配结果展示空状态。未知博客分类保留，非法友链类别由 schema 拒绝，不静默丢条目。写作热力遇到非法日期在构建时抛错；没有已发布文章时不渲染，不补第一篇文章之前的空年。正文容器为空的页面让构建失败（见[正文与媒体](./content.md#html-media)）。
- 导航 pending 状态由对应 AbortSignal 拥有；后发目标替代先发目标，过期取消不能回退最新预览；只有 pathname 追上 pending 目标才完成预览，已排队的旧交换不能冒充另一个新目标完成。页面加载后的实际路径最终决定选中父级。
- 分类入口数随已发布分类数增长，菜单受视口高度约束并可滚动；改分类名视为新分类，领取新配色，旧映射仍保留，不提供自动的分类改名迁移服务。
- 分类配色记录仅在有新分类且容量充足时通过临时文件替换更新；缺失／损坏记录、重复或无效配色、配色池耗尽、写入失败均明确报错，不部分领取或静默复用颜色。记录供本地单写者维护，不支持多个 dev／build 进程同时分配；CI／Vercel 不会自动将生成的记录提交回仓库。
- 菜单预览每类最多四篇，首页最多五篇；文稿每页八篇，但静态 HTML 仍包含全量已过滤文章以支持无脚本回退，分页不按页发起网络加载。
- 导航更新用 rAF 合并；时间进度每 30 秒更新，页面交换前清除旧定时器。TOC 监听／观察器在连接时建立、断开时清理，字体完成回调只处理仍连接的元素。
- RSS逐篇处理，无部分 feed、无持久恢复状态；不新增文章数量或未来日期过滤上限。图片和字体由构建管线管理，失败构建不能作为成功产物发布。
- 复制友链模板失败给出“复制失败”反馈；无 JS 时模板仍可选取复制。搜索只按需加载现有 Pagefind；索引范围由搜索配置控制。

<a id="limits"></a>

## 6. 支持范围和限制

- 文章 slug、域名和 base 决定永久地址；没有独立的文章改名或换域名 ID 服务。
- RSS 使用基础 HTML 和公式源码，不保证与网站或不同阅读器的像素样式一致。
- 新增顶栏项或拾趣分类需验证导航宽度、换行和响应式布局；下拉菜单受视口高度约束并可滚动，自动收录不意味着任意数量或长度都保证布局可用。
- 开发网页列表和正文可预览草稿；生产不可含草稿。首页摘要、写作热力、顶部分类菜单和开发／生产 RSS 只使用已发布集合；草稿不参与菜单入口、计数或最近文章，不保留仅含草稿的分类或空已发布集合的分类入口。
- `search: false` 与 RSS 范围独立，禁用搜索不等于不发布。博客文章是否下线由删除或草稿状态决定；拾趣没有草稿开关，移除分类文件后重新构建才移除对应子页、入口和菜单项。
- 目录最后的短章节可能无法滚到激活线，页面底部规则负责选中它；历史返回恢复浏览位置，不强迫 hash 标题重新对齐。

<a id="verification"></a>

## 7. 验收入口

测试保护功能正确性、内容完整性、安全和可用性。算法与边界测试使用固定夹具；热力图弹层检查自行构造同日多篇场景，不要求真实内容存在同日多篇。构建检查从当前配置、内容及产物推导预期，地址通过 `SITE.website`／`SITE.base` 和 URL 生成，不锁定根路径部署；不把个人账号、文章标题、友链名单、兴趣分类数量、观看状态或具体 CSS 写法另设为不可修改规则。视觉调整通过实际可读性、视口边界和交互效果验证，不用调色板或像素值快照阻拦正常调整。

按 [开发与部署指南](../guides/development.md#verification) 执行仓库检查，并按改动范围选择页面、正文、RSS 或外部服务验收。浏览器检查需覆盖深浅主题与 1440／390／320px，目录另检查 1200px 阈值及不同高度；发布预览与本地测试不能替代实际部署或阅读器验证。
