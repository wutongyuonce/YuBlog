# 博客重构 SPEC 与实现设计

本文件是本次重构的最终行为契约与模块职责说明。适用于 `codex/blog-restructure` 相对 `4f29745` 的变化；RSS 全文功能已在该基线实现，本次保留它的接口与安全边界。最终交付包括实现、内容迁移、回归检查、作者操作说明和 PR，不包含线上部署或合并 PR。

## 1. 背景、参与者与范围

旧首页兼任文章列表，个人侧栏出现在多个页面；关于页混合作者介绍和多种兴趣，导航与正文目录的动画在子页切换时出现重复定位。此次将首页改为作者入口，把完整浏览交给文稿页，拆出拾趣，统一窄版心与导航状态，并保留既有文章 URL、标签筛选、分页、图片管线、搜索和全文 RSS。

参与者是访问首页的读者、按分类或标签找文章的读者、通过目录阅读长文的读者、订阅 RSS 的读者及维护内容的作者。验收以用户可见行为和属主接口为准，不以测试数量或绝对“不会闪烁”作为保证。

| 页面 | 路由 | 最终职责 |
| --- | --- | --- |
| 首页 | `/` | 时间进度、作者、RSS、名言、写作统计、六个社交入口和最近五篇文稿 |
| 文稿 | `/blogs/` | 全量文章列表、分类／标签筛选、每页七篇 |
| 分类 | `/blogs/#tech`、`#thought`、`#diary` | 同一文稿页的技术、思考、日记状态，非独立静态页面 |
| 标签 | `/tags/` | 标签目录、排序、多选 AND 筛选；无选择时不显示文章列表 |
| 归档 | `/archives/` | 单条时间线，按年组织，分类徽标辅助识别 |
| 拾趣 | `/interests/` | 七个分类入口 |
| 拾趣子页 | `/interests/device\|anime\|movie\|tv\|game\|book\|kpop/` | 对应内容，标题不带“拾趣-”前缀 |
| 项目 | `/projects/` | 页头和按 JSON 分类的项目卡片 |
| 关于 | `/about/` | 页头及作者介绍；无 About／Use／Hobby／Soul 切换 |
| 友链 | `/friends/` | 推荐、双向两组卡片及交换说明 |
| 正文 | `/blogs/<slug>/` | 独立标题、可选封面、正文和目录 |
| 订阅 | `/rss.xml` | 全部生产已发布文稿的完整正文，不包含页面壳或交互 |

## 2. 用户场景与产品规则

### S1：首页认识作者，再进入文稿

首页顶部先显示三列细时间进度。头像、梧桐雨、INTJ 作为一组水平居中，桌面 RSS 在同一行右侧；600px 及以下 RSS 单独居中一行，避免挤压作者。下方依次居中排列「我与我周旋久，宁做我」、用中点分隔的文章／字数／写作天数、六个社交图标。社交入口保留名称供读屏和悬停提示，沿用关于页五个身份加真实邮箱，不编造账号。

首页最近五篇只包含已发布文章；每项有标题、分类与日期，标题在悬停和键盘焦点时出现下划线。全部文稿进入 `/blogs/`。旧首页的 `?page=`、`?category=`、`?tag=` 书签在启用脚本时替换为文稿页地址，保留参数和 hash；无脚本时首页仍可阅读。

### S2：分类、标签和分页

技术包含原“技术向／工具向”及明确别名；思考包含原“思考向”；日记包含“日记／日记向”。未知分类保留其原值，不归到兜底类别。首页、导航预览、列表与归档共用分类映射，不要求修改所有旧文章 frontmatter。

文稿先对全量数据筛选，再分页，每页七篇。类别 hash 优先于旧 `?category=`；重复标签归一化、多选为 AND。修改筛选回第一页，分页保留筛选，越界页回到有效页，前进／后退恢复 URL 状态。首屏不先展示不匹配的第一页；禁用脚本时文稿展示全量文章及说明，标签页保留标签目录和启用脚本提示。

两篇“东亚的孩子，能不能不靠成绩来换爱？”和“INTJ 最稀缺的一种能力：Antifragile”映射到思考。日记增加一篇明确说明用途的占位文章，`search: false`，但不标为草稿，因此仍进入生产列表、归档和 RSS。

### S3：顶栏和下拉菜单

品牌“梧桐雨的博客”是首页入口；其余按钮为文稿、标签、归档、拾趣、项目、关于、友链，右侧保留本仓库 GitHub、搜索和主题开关。首页品牌为粉色并轻微加厚，字宽不因选中而变化；其他当前项浅色黑底白字、深色白底黑字，未选中项悬停使用灰底。

文章及文稿分类属于文稿，拾趣子页属于拾趣。导航配置的尾斜杠不改变菜单或父级选中；服务端与客户端从 `nav-path.js` 读取同一规则，支持站点 base。滑块只使用顶层按钮坐标，同一父级内切换保持原位；文章入口无论来自标签、归档、首页、列表或菜单，都在导航准备阶段定位文稿。页面交换前后不重建滑块，不从零位置补播。最新导航目标拥有预览，旧请求取消不得撤回新目标；导航失败或被取消时恢复已加载页面的状态。`aria-current` 描述已加载页面，目标预览使用独立属性。

文稿菜单左列三个分类位置固定，右列最多四篇当前类别的最近文章；穿过行间空隙或右侧沟槽保留当前类别，不回退第一项。文章标题悬停／焦点有下划线，底部查看全部文稿行保持紧凑。拾趣菜单读取集合元数据，图标、标题、说明与入口一致。

桌面 hover 或键盘焦点展开，触屏首次点名称展开、再次点进入入口页；ArrowDown／空格进入菜单，Enter 正常导航，Escape（包括仅鼠标悬停、焦点在菜单外时）和外部点击关闭。无脚本仍可通过 hover／focus 使用链接。

顶部 80px 内导航保持可见；同方向累计滚动 18px 后下滑隐藏、上滑显示。键盘焦点、打开的菜单或搜索会保持导航可见；页面切换恢复可见。减少动态效果偏好下关闭相关过渡。

### S4：兴趣和内容迁移

拾趣入口与七个子页均使用点状背景，说明由各 Markdown 元数据维护。设备承接原 Use；动漫含国漫、电影含动画电影、电视剧含综艺，其余游戏、书、Kpop 独立。游戏说明为“热爱的虚拟世界”，书为“翻过的扉页”，Kpop 为“喜欢的团体与idle”（保留用户指定拼写）。原内容和图片迁移不丢失；Soul 源文件保留但不展示，不再创建关于页标签。

### S5：归档和友链

归档按共享发布日期顺序排成一条时间线，年份为宋体 22px，日期为宋体；日期在原日期列内右对齐，靠近时间线，年份位置不变。日期、标记与标题首行共用 24px 行高。所有分类的小点均为灰色，悬停／焦点均为粉色短竖线；标题右侧的圆角徽标包含分类文字，不能仅靠颜色区分。

友链 category 仅允许“推荐”或“双向”。Anthony Fu、pseudoyu、阮一峰、Armin Ronacher 为推荐，其余保留条目为双向，删除吐槽大王部落格。组内沿用 `order`／名称排序，两组用较小宋体标题及说明分隔，“交换友链”同样使用宋体。卡片悬停／焦点加强边框和名称颜色，不整卡变灰或让头像发光；深浅主题可读，窄屏改为单列。

### S6：有封面和无封面文章

文章始终保留一个独立宋体 h1 及原有日期／阅读时长／标签信息，不保留标题下装饰短线。有封面时在其下渲染图片卡片：重复标题用段落，描述取 `description`、缺失时取 `subtitle`，作者行只含 40px 头像、梧桐雨与日期。封面白字和深色渐变遮罩适配两种主题。无封面时保持标题和正文结构，不构造假封面。

桌面 1200px 及以上目录常驻、无顶部 TOC 按钮；小屏保留浮动目录入口。目录靠近正文，外侧间隔 48px，最大宽度 208px，受剩余空间约束，垂直居中；高度不超过 `min(50vh, 28rem)`，长目录在内部滚动，当前项移入可视范围。

目录点击与章节高亮共用阅读边缘：导航隐藏为 20px，显示为其顶部位置、实际高度再加 12px。点击前从共享模块维护的实际累计滚动状态预测显隐（预测不修改状态），让原生 fragment 滚动直接使用目标距离，不进行第二次补滚。滚动、字体／图片布局变化、缩放和导航显隐重新同步；到页面真正底部最后章节胜出。保留正常 URL hash 和历史返回语义；离开文章后清理监听、观察器及临时定位变量。无脚本时保留可见导航所需的静态间距。

### S7：文章与 RSS 共用内容管线

页面结构变化不进入 RSS。endpoint 继续只渲染集合 `Content`，经静态 HTML 转换输出 `content:encoded`；摘要共存，订阅地址、GUID、发布日期、redirect 语义与完整正文范围不变。封面布局、头像行、导航、目录、主题 CSS／JS 不进入源；正文图片仍来自 Astro 解析的资源并变成站外可访问 URL。

不抓取 redirect 目标、不下载远程媒体，不用第二个 Markdown 解析器。生产排除草稿、开发遵循现有内容工具；任一文章渲染或转换失败使本次生成失败，不静默漏文或退回摘要。完整规范见 [RSS 全文支持 SPEC](./RSS%20全文支持%20SPEC.md)。

## 3. 视觉不变量

| 对象 | 最终规则与属主 |
| --- | --- |

| 导航 | `shell.css` 管理外框 4px、按钮／滑块 2px 圆角，紧凑一行，窄屏两排；友链后留约一个工具按钮宽度 |
| 字体 | `--font-heading` 为本地思源宋体 400；页面主标题、文章顶部标题、作者、近期笔墨、归档时间用它；列表标题、Markdown 内部标题、正文、导航和标签用 Inter／系统无衬线；代码用 DM Mono |

| 主题与焦点 | 颜色源于 `--c-bg`、`--c-text`、`--accent`；提供深浅主题及可见键盘反馈，不依靠颜色表达类别 |

## 5. 失败、并发和资源语义

- 静态内容在构建时验证。缺少作者介绍或无效 schema 明确报错；无文章／无匹配结果展示空状态。未知博客分类保留，非法友链类别由 schema 拒绝，不静默丢条目。
- 导航 pending 状态由对应 AbortSignal 拥有；后发目标替代先发目标，过期取消不能回退最新预览；只有 pathname 追上 pending 目标才完成预览，已排队的旧交换不能冒充另一个新目标完成。页面加载后的实际路径最终决定选中父级。
- 菜单预览每类最多四篇，首页最多五篇；文稿每页七篇，但静态 HTML 仍包含全量已过滤文章以支持无脚本回退，本次不承诺按页网络加载。
- 导航更新用 rAF 合并；时间进度每 30 秒更新，页面交换前清除旧定时器。TOC 监听／观察器在连接时建立、断开时清理，字体完成回调只处理仍连接的元素。
- RSS逐篇处理，无部分 feed、无持久恢复状态；不新增文章数量或未来日期过滤上限。图片和字体由现有构建管线管理，失败构建不能作为成功产物发布。
- 复制友链模板失败给出“复制失败”反馈；无 JS 时模板仍可选取复制。搜索只按需加载现有 Pagefind；本次不扩展索引范围。

## 6. 非目标和取舍

- 不改已有文章 slug、日期或正文事实；不新增旧 slug 重定向服务，不部署、不自动合并。
- 不升级依赖，不改 RSS 全文安全策略，不增加阅读器 CSS，不保证阅读器与网站像素一致。
- 不保证任意新增顶栏数量仍能放进现有宽度；新增导航需重新验证响应式布局。
- 开发环境列表和 RSS 按既有行为可含草稿；生产不可含草稿。首页摘要／预览使用已发布集合。
- `search: false` 与 RSS范围独立，禁用搜索不等于不发布。占位日记如要下线由作者删除或改为草稿。
- 目录最后短章节可能无法滚到激活线，页面底部规则负责选中它；历史返回恢复浏览位置，不强迫 hash 标题重新对齐。

## 7. 验收入口

1. `pnpm test`、`pnpm check`、`pnpm lint`、`pnpm format`、`pnpm build`。
2. 构建后 `pnpm test:built-restructure`、`pnpm test:built-pagination`、`pnpm test:built-markdown`：集合范围、内容迁移、友链分组、目录、封面语义、图片／RSS资源。
3. 在现有 Ego TaskSpace 中运行 `sed 's/__TASK_SPACE_ID__/<id>/g' scripts/verify-nav-dropdown.mjs | ego-browser nodejs` 和同样的 `verify-toc-navigation.mjs`；脚本不创建或结束 TaskSpace。
4. 深浅主题、1440／390／320px检查：首页作者中心、进度顺序、页头一致、归档日期对齐、卡片、点状背景、目录靠正文且居中、无横向溢出。目录另检查1200px阈值和不同视口高度。
5. 独立两轮 GPT-6.1 Sol 审查，第二轮额外检查模块边界、唯一权威、废弃代码和文档漂移；修复后复验最终差异。结果写在 PR／审查记录，不将逐轮过程写进最终契约。

本地证据不替代 GitHub CI；PR 创建后核对当前提交的 CI。Safari／Firefox 和实际阅读器视觉未在本轮验证，需与本地和 Chromium 结果区分。
