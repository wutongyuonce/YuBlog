# YuBlog 架构与实现

本文是开发导览，解释目录结构、模块权威、调用边界和运行链路，帮助定位修改应落在哪个文件。页面规则、视觉数值及验收义务以站点行为 SPEC 为准；本文说明它们如何实现。改文案和数据走内容 skill；改行为先看本文件的**权威**和 **seam**，再动对应模块。Astro 语法见 [Astro.md](./Astro.md)，SEO 见 [Canonical URL、Sitemap、RSS.md](./Canonical%20URL、Sitemap、RSS.md)。

页面行为与模块职责见 [站点行为 SPEC](./站点行为%20SPEC.md)，变更记录见 [CHANGELOG](../CHANGELOG.md)。

本文用这些词：

- **模块**：有界面、有实现的一块（函数、文件、页面拼装都可以）。
- **界面**：调用方必须知道的全部事实：签名、不变量、错误、配置、性能。
- **实现**：模块里面的代码。
- **seam**：界面所在的位置；可以在这里换实现、而不改调用方。
- **权威**：某类事实只允许在一处定义。别处只能读，不能再发明一份。

## 1. 这是什么站

Astro 7 静态站。主路径是**读文章**：首页名片、写作热力与近期笔墨、文稿列表、标签筛选、年份归档、文章详情。文稿、标签、归档、拾趣、项目、关于、友链共用同一套居中单栏布局与悬浮导航。黑白主题，配置集中在 `src/config.ts`。

线上：`https://www.wutongyu.site/`。

构建：`pnpm build` → `dist/`（不进 git）→ `postbuild` 跑 Pagefind，再跑 `scripts/postbuild.mjs`（清理 Pagefind UI 文件）与 `scripts/check-content-rendered.mjs`（校验全站每个正文容器确实渲染出了内容，包括关于、拾趣，空正文让构建失败）。

## 2. 页面地图

| 路由 | 人看到的 | 入口 | 数据权威 |
| :--- | :--- | :--- | :--- |
| `/` | 作者介绍、写作热力、近期五篇笔墨与近期书影游 | `src/pages/index.astro` | 已发布 `blogs`、`interests/recent.md` |
| `/blogs/` | 完整文稿列表，七篇分页，原始分类共用 URL 片段精确筛选 | `src/pages/blogs/index.astro` | `blogs` 集合 |
| `/interests/`、`/interests/<id>/` | 分类入口与按内容自动生成的独立页面 | `src/pages/interests.astro`、`src/pages/interests/[id].astro` | `interests` 集合：顶层 `*.{md,mdx}`，排除 `intro.md`、`recent.md` |
| `/tags/` | 标签芯片；多选 AND；未选不列出文章 | `src/pages/tags.astro` | 同上，标签从文章 frontmatter 汇总 |
| `/archives/` | 按年时间线 | `src/pages/archives.astro` | 同上，按 `pubDate` 分组 |
| `/projects/` | 分类网格 | `src/pages/projects.mdx` | `src/content/projects/data.json` |
| `/about/` | 作者介绍 | `src/pages/about.mdx` | `src/content/about/about.md` |
| `/friends/` | 友链卡片 + 申请模板 | `src/pages/friends.mdx` | `src/content/friends/data.json` |
| `/blogs/[slug]/` | 正文、右侧 TOC | `src/pages/blogs/[...slug].astro` | 单篇 `blogs` |
| `/rss.xml` | 订阅源 | `src/pages/rss.xml.js` | 已发布 `blogs`（不含拾趣或 `recent.md`） |

顶栏页面链接由 `src/config.ts` 的 `UI.internalNavs` 维护；更多菜单由 `MORE_LINKS` 提供友链及相册条目，友链页对应更多选中态。相册链接指向独立部署的 `https://photos.wutongyu.site/`，带 ↗ 并在新标签页打开。拾趣与更多下拉框最大宽度 200px。工具组读取 `UI.socialLinks` 中的本仓库 GitHub 链接，并包含搜索和主题按钮。个人社交由 `AUTHOR_LINKS` 维护：首页 GitHub 指向个人主页，与 X、Instagram、Bilibili、小红书、邮箱一起展示；关于正文独立维护作者希望公开的联系方式。

`nav-path.js` 统一导航路径归一化、下拉类型和父级选中，服务端 `NavBar`／`NavItem` 与客户端共用规则；配置的尾斜杠及站点 base 不改变结果。

`NavBar.astro` 负责导航滑块：Astro 确认接管任意站内链接时，先按链接目标路径解析其顶层按钮，再把滑块移向该按钮，旧正文继续显示。拾趣子页统一对应「拾趣」，文稿分类和最近文章统一对应「文稿」；同一父级内切换保持滑块原位。下拉链接的 offset 相对于面板，不能用来定位顶栏滑块。标签、归档、首页近期笔墨等正文入口即使位于顶栏之外，也在导航准备阶段更新文稿高亮，不能等到页面交换完成才补播。

滑块的不透明底色需要标签同时换色，所以有两个属性：`aria-current` 始终表示用户真正所在的页面（给读屏器和「当前页」语义），`data-nav-current` 表示滑块画在哪个项上（给 `shell.css` 的配色），导航预览期间只有后者会先走。

`astro:page-load` 也会由 window load 或上一次导航触发，因此只有 pathname 已追上当前 pending 目标时才清除预览，已排队的旧页面交换不能冒充新目标完成，否则保留待导航状态。

前进／后退也从 Astro 事件目标 URL 解析父级；after-swap 在新页面绘制前同步最终高亮，page-load 再做幂等核对。只有当前请求的取消信号可撤回预览，旧请求不能撤回更新的导航。返回首页收起滑块并清除动画起点，下次显示直接定位。字体就绪与缩放期间不打断待导航的目标。品牌在首页带 aria-current，粉色及轻微文字加厚不改变它的宽度。外链、新标签页与浏览器默认处理的点击不走预览。

背景：首页 / 文稿 / 标签 / 归档 `dot`，项目 `rose`，友链 `snow`，拾趣及子页 `dot`，关于关闭。权威是各页传给 `BaseLayout` 的 `bgType`。

`dot` / `snow` 是 canvas 动画（`src/components/backgrounds/`）：

- `prefers-reduced-motion: reduce` 时只画一帧静态背景，不启动 RAF 循环，并在系统设置变化时启停。
- `dot` 每帧按透明度分 6 档批量描边。布点规则在 `Dot.astro`：基础间距 15px；估算点数超过约 8000 时按面积放大间距。这是密度目标，边缘补点可能超过它，不是硬上限。

## 4. Seam：该从哪切开

### 4.1 内容 seam

界面：Content Collections + Zod。  
实现：磁盘上的 md / json。  
调用方：`getCollection` / `getEntry` / `src/utils/data.ts`。

内容字段先在 schema 约定，页面读取集合。拾趣分区的标题、说明、顺序来自 Markdown；在 `src/content/interests/` 顶层新增 `.md` / `.mdx` 并满足 schema 字段，重新构建后页面、入口和菜单自动生成，不固定分类 ID 或数量。可选图标映射在 `config.ts` 的 `INTEREST_ICONS`，键为文件名去掉扩展名；不配图标时菜单显示纯文字，不渲染图标占位。关于页只读取 `about.md`，新增 Markdown 不会自动变成页签。

### 4.2 列表数据 seam

界面：`getFilteredPosts`、`getSortedPosts`、`getBlogListItems`、`getGroupedPostsByYear`、`getRecentBlogPosts`、`getPublishedBlogPosts`。
实现：草稿过滤、日期排序、渲染 `minutesRead`、按年 reduce。

首页、文稿、顶部分类预览、标签、归档、RSS、名片、近期笔墨都应穿过这里取文章集合。顶部分类菜单和开发／生产 RSS 均只读取 `getPublishedBlogPosts`；开发网页列表／正文仍可预览草稿，不属于菜单排除草稿的设计边界。写作热力只从这里取已发布文章，按日聚合篇数，并按上海自然年汇总字数，规则在 `blog-heatmap.js`（`test/blog-heatmap.test.mjs`）。字数格式测试见 `test/blog-stats.test.mjs`。

### 4.3 浏览器状态 seam

界面：`serializeBlogQuery` / 解析查询串（`blog-browser.js`）。  
实现：`category`、`tags[]`、`page`、每页 7 篇。

`ListView` 负责把 DOM 和这个状态接上。改每页数量时，除了 `blog-browser.js` 和测试，还须同步 `ListView.astro` 的首屏 CSS `nth-child(n + 8)`（CSS 选择器不能读取 JS 常量）；标签匹配的 AND/OR 规则在 `blog-tag-filter.js` 的匹配接口修改，`blog-browser.js` 只调用它，不要在点击处理里复制判断。

页码窗口由 `getPageNumbers` 统一生成，包含省略号最多 6 项（上一页 / 下一页另计）：总页数 ≤6 时全部显示；>6 时，优先判断当前页 ≤4，显示 `1 2 3 4 … N`；否则当前页 ≥N−3 显示 `1 … N−3 N−2 N−1 N`；其余显示 `1 … p p+1 … N`。省略号不可点击，至少代表两页；首尾和当前页始终可见。中间窗口优先展示下一页，无法同时保留前后邻页时可用独立的上一页 / 下一页控件连续翻页。生成窗口的计算和输出大小不随总页数增长。

`ListView` 负责标记当前页、禁用首尾的上一页/下一页，以及在 0 或 1 页时隐藏分页。分页渲染成一行胶囊条：两端是同一枚箭头（`‹` / `›`，用 `aria-label` 给出「上一页 / 下一页」），中间是页码窗口，当前页画成填充块。`>480px` 时单项 `2.25rem`；`≤480px` 时单项降到 `1.9rem`、列间距降到 `0.25rem`、页码间距归零，让「箭头 + 六项窗口」共 8 项在 320px 视口内仍保持一行而不横向溢出。分页视觉统一放在 `public/shell.css`，由文稿和标签页共用，组件通过同一份样式呈现。页码边界和 1–50 页所有有效当前页组合由 `test/blog-browser.test.mjs` 验证。

### 4.4 壳层样式 seam

界面：`public/shell.css` 的 class（`header.nav-bar`、`.blog-profile`、`.archive-*`、`.nav-dropdown`、`[data-pagination]`）。
加载：`Head.astro` 里真正的 `<link rel="stylesheet">`。

硬刷新和 ClientRouter 使用同一份样式：Vite 输出一个 `_astro/style.*.css`，每页另加载 `/shell.css`。组件局部样式在两种加载方式下均有效。`shell.css` 维护跨页壳层规则及构建后字体子集引用；正文与 Markdown 规则在 `src/styles/`，友链卡片等组件样式由对应组件维护。目录链接的共享规则在 `main.css`，桌面目录位置和尺寸分别由 `DesktopAside`、`TocSidebar` 管理。共享规则集中维护；组件可以按需局部覆盖，以硬刷新和跨页导航中的实际效果验证，不将跨文件同名选择器一概判为错误。

KaTeX 样式与字体来自本地 `katex` 包，由 Vite 打包到 `/_astro/`；版本与公式渲染依赖一致，浏览器按实际页面内容加载所需字体。

`--font-heading`（本地思源宋体 400 字重）用于页面大标题、文章顶部标题、作者名、写作热力与近期笔墨；文稿列表与归档文章标题使用同一宋体，字重分别为 700 与 400，分别由 `ListItem.astro` 的 `.post-preview h2` 和 `shell.css` 的 `.archive-post__title` 维护；标签筛选结果复用 `ListItem`。字体资源提供 400 字重，700 由浏览器合成加粗。Markdown 内部 h1–h6、正文和标签使用 Inter／系统无衬线字体。顶栏及下拉菜单文字使用宋体；品牌为「梧桐雨の博客」，使用桌面 16px、601–799px 为 14.72px、600px 及以下为 14.4px 思源宋体，行高 1；归档年份与日期也使用思源宋体。`PageHeading` 是标签、拾趣（含子页）、项目、关于的共享页头：标题 28px 宋体 400 字重，说明 14px 普通字体；友链分组标题为 24px 宋体。

正文字体 Inter 和代码字体 DM Mono 也在本地：`public/fonts/Inter-latin.woff2`、`public/fonts/DMMono-latin.woff2`，由 `src/styles/main.css` 的 `@font-face` 引用。不要再接 Google Fonts 或 `presetWebFonts`。这两份只含拉丁字符，中文走字体栈后面的系统字体。保留的两种手写字体 `@font-face` 在 `public/shell.css` 中，优先引用构建结束后生成的 `*-title.woff2` 子集，再回退到完整字体；`plugins/astro-subset-title-fonts.ts` 在构建后检查每个子集引用和文件都存在。Vite 不会提前解析尚未生成的字体路径。开发服务器没有子集时会回退到同一次声明里的完整文件，那不是线上行为。

主题、搜索、回顶、遮罩的点击在脚本执行时就绑定，不等第一次 `window` `load`。`astro:page-load` 只负责换页后的新节点，并用元素上的 `dataset` 避免重复绑定。

主题由根元素的 `dark` class 表示；`Head.astro` 仅恢复合法的 `light`／`dark` 保存值，缺失或非法时回退系统，`ThemeSwitch.astro` 负责手动切换及系统模式变化。两处的 `color-scheme` meta 只声明当前方案；存储读写失败不打断显示和切换，但不保证跨导航／刷新保留选择。`main.css` 的根元素规则同步 `only light`／`only dark`，声明原生控件和页面画布的当前配色，禁用浏览器常规自动暗化；外部暗化工具仍可能覆盖实际样式，页面不保证其覆盖后的配色与主题按钮一致。

`theme-observer.js` 订阅实际主题变化，忽略转场等无关 class 更新；Dot／Snow 在变化时重绘，并在断开时退订。页面交换先连接背景再恢复主题时，也会按最终主题补画；减少动效时不启动动画循环。`scripts/verify-theme-refresh.mjs` 在真实浏览器中验证首访、非法或不可用存储、系统偏好与保存主题相反、按钮切换、连续刷新、实际背景像素及 ClientRouter 导航后的恢复与资源清理。

`plugins/postcss-katex-woff2-only.ts` 挂在 `vite.css.postcss`，在 Vite 生成 CSS 产物**之前**把 KaTeX `@font-face` 里的 woff / ttf 源去掉。因为发生在产物生成前，CSS 文件名的哈希仍然对应所服务的字节；不能改到构建后处理（那时文件名已经定下）。上游 KaTeX 若变结构，插件会报错而不是静默产出坏字体。

装饰背景层级由 `src/styles/main.css` 的 `body { isolation: isolate }` 统一维护；点阵、雪花和 rose 保持 `z-index: -1`，在主体内部位于底色之上、内容之下。主体底色不遮挡背景，隔离层级不改变 fixed 元素的视口定位。`scripts/verify-background-layering.mjs` 用不透明主体底色和截图像素验证静态／动画点阵的可见性、滚动定位及换页，不仅检查 Canvas 缓冲区。

### 4.5 布局 seam

- `BaseLayout`：文档头、背景、悬浮导航、主槽、页脚。文档头由 `Head.astro` 输出，其中一份 Umami Cloud 脚本只负责访问统计，不渲染界面。脚本带 `is:inline` 和 `defer`；不要加 `data-astro-rerun`，也不要在 `astro:page-load` 再调用 `umami.track()`，避免换页重复计数。
- `BlogIndexLayout`：导航页面的居中单栏容器。
- `StandardLayout`：文章标题、正文与普通内容排版。

全站没有个人右侧栏；`BlogProfile` 只在首页出现，其下依次是 `WritingHeatmap`、`RecentWriting`、`RecentMedia`。导航页统一通过 `BlogIndexLayout` 限制宽度。文章详情使用 `StandardLayout`，TOC 独立放在正文外侧。

顶栏的 `--site-nav-width` 引用 `--blog-shell-width`，与内容版心共用 660px 目标；更多右侧保留剩余空白。内容宽度同时受 `100vw - 两侧外边距` 限制；1200px 及以上再减去 32rem，避免加宽正文时把目录从 208px 挤窄。顶栏与正文同步收窄，小屏两排导航仍受响应式外边距 `--site-gutter` 约束。`--blog-prose-width` 引用版心宽度，标题、正文与返回链接对齐；目录读取同一个 `--blog-prose-width`，在正文边缘与视口外边距之间的留白中线基础上向外移 16px，最大 208px、受视口剩余空间约束。文稿列表卡片的封面列固定为无图 222px、有图 250px，版心宽度变化只进入左侧文字；768px 及以上封面垂直居中，更窄时改为单列并隐藏空封面列。目录与正文读取同一版心宽度。小屏由可用视口宽度约束。

导航是一条有细边框、轻阴影和柔和当前态的居中悬浮条，品牌、页面入口、工具按钮分组。≥800px 为一排，更窄视口为品牌／工具和页面入口两排。用 `top` 与 opacity 隐藏，不在包含搜索面板的祖先上使用 transform 或 backdrop-filter，保证搜索弹窗仍相对于视口定位。

所有页面的初始顶部位置由 `shell.css` 的 `.site-main` 统一维护：桌面顶部内边距 104px，799px 及以下 136px，扣除顶栏占位后留白约 40px／36px。目录点击后的锚点间距仍由 TOC 单独维护，不用初始页面留白推断滚动落点。

### 4.6 导航与首页 seam

`nav-scroll.js` 负责滚动方向与阈值：顶部 80px 内始终显示；同方向累计 18px 后下滑隐藏、上滑显示。`NavBar` 将其结果呈现到 `data-scroll-hidden`，每帧最多处理一次，菜单展开、键盘焦点或搜索打开时保持可见，跨页导航重置。无脚本时导航保持显示；减少动态效果时关闭过渡。

部署层保留 `/blogs/` 的静态列表路由，`vercel.json` 不配置将 `/blogs` 或 `/blogs/` 指向首页的重定向。名称编码分类片段及旧 `#tech`／`#thought`／`#diary` 兼容链接共用此路由，因此部署重定向会同时破坏菜单入口和分类筛选；本地 Astro preview 不读取 Vercel 重定向，构建回归另检查部署配置。

文稿菜单由 `NavDropdown` 保存当前预览分类，只在实际分类链接的 pointerenter／focusin 时切换，鼠标走过行间隙时保留选择；无脚本的 hover／focus 降级仅应用于未绑定脚本的菜单。Escape 的文档级监听关闭已展开菜单，包括鼠标悬停展开但焦点仍在菜单外的情况；只有焦点原本在该菜单内才返回触发链接。浏览器回归脚本为 `scripts/verify-nav-dropdown.mjs`。

顶部分类菜单只读取 `getPublishedBlogPosts`，由 `blog-browser.js` 的 `getCategoryPreviews` 按 `data.category` 原值统计分类，保留每类最多四篇已发布文章预览，发布日期顺序不变；入口按篇数降序，同数按名称的 `zh-Hans-CN` 排序。`draft` 不参与入口、计数或最近文章，是明确的设计决策边界：仅含草稿的分类消失，删除最后一篇已发布文章后对应入口消失；已发布集合为空时类别为空，仅保留“查看全部文稿”链接，不保留固定类别。开发网页列表与正文预览不属于此边界，行为不变。菜单 URL 通过共享 `serializeBlogQuery` 生成。桌面左列与右列各占一格：左列固定间距自上而下，右列只显示当前预览；面板高度取较高的一列，未选中预览不占高度，所以切换分类不移动左列。右列在面板滚动时保持可见，小屏仍逐类排列。写作热力的上海日历与年度汇总在 `blog-heatmap.js`；进度数字在 `progress-stats.js`；近期五篇在 `getRecentBlogPosts`（与列表筛选无关）。近期五篇仅在首页显示。三块首页板块标题共用 `shell.css` 的 `.home-section-header`，各自内容样式留在组件或共享正文样式；热力提示层的焦点、滚动限高、定时器与监听清理由 `WritingHeatmap` 唯一持有，页面交换前清理。

### 4.7 TOC seam

`FEATURES.toc` 决定开不开、标题层级、左右。
`TocSidebar` 负责高度（不超过 `min(50vh, 28rem)`）和内部滚动。
`DesktopAside` 在 1200px 及以上始终显示目录，无顶部开关；宽度为侧边留白减 48px 与 208px 中的较小值，靠正文一侧至少留 40px、外侧至少留 8px（另有视口外边距）；在正文边缘与视口外边距之间的留白中线基础上向外移 16px，中心比视口中线高 32px。更窄视口继续使用 `MobileTocControl` 浮动入口，展开时通知共享目录逻辑将当前项滚入可视范围。

当前章节由 `src/utils/toc-active.js` 的 `pickActiveHeadingIndex()` 决定：激活线取标题的 `scrollMarginTop`，到页面底部时最后一个标题胜出。`Toc` 唯一维护 `--post-anchor-offset`：导航隐藏时 20px，显示时为导航顶部位置加实际高度再加 12px。`nav-scroll.js` 唯一保存累计滚动状态，`NavBar` 用 `updateNavVisibility()` 更新它；点击前 `Toc` 用 `predictNavVisibility()` 从同一状态预测导航显隐，不消耗累计距离，原生锚点直接消费对应距离；滚动、导航显隐、缩放和字体加载后重新核对同一基准。保留正常 fragment 与历史记录行为，不补播第二次滚动。正文标题仅使用透明度入场，锚点位置不随入场动画变化；无脚本时保留导航可见所需的静态距离。

正文 `:::card` 由 `plugins/remark-media-card.ts` 渲染，样式在 `prose.css`：右上角类别、左侧相对路径封面、右侧可外链标题、可选评分和可滚动介绍；连续卡片组成自适应网格。评分以真实文本提供给读屏与 RSS，星星只是装饰；最多一张独立 Markdown 封面，介绍仅允许文字排版和链接；插件递归拒绝额外图片、HTML／静态 MDX 嵌入媒体及指令生成的媒体（按有效 `data.hName`／`data.hChildren` 检查），违规、非法分数或嵌套卡片均使构建失败，不删内容。普通 HTML 文字排版、注释和代码示例不误判为媒体；危险标题链接降级为纯文本。封面仍走图片管线。博客、拾趣、关于共用这条管线，所以这些页面的 Markdown 都能写。博客、拾趣、首页近期书影游和关于正文共用 `prose.css` 的 `.prose.markdown-content` 标题规则；h1／h2／h3／h4–h6 依次为 2.125rem／1.6rem／1.1875rem／1rem，其他正文排版仍按各自容器维护。`plugins/index.ts` 只给标题生成 ID 和单个 `#` 锚点，不归一化标题深度；Markdown 中 `##` 即 h2，即使正文没有 h1 也保持 h2。博客目录按配置收录 h2–h4，不会把最高级章节改成 h1。

桌面目录各级标题在收窄后的栏宽内完整换行；当前项超出内部滚动区域时，`Toc` 将它滚回可视范围。

### 4.8 图片 seam

**界面**：内容里的相对图片路径（`./<目录>/文件.png`）、frontmatter 的 `titleImage: image()`、alt 尾部的宽度标记 `|w480`。  
**实现**：`astro.config.ts` 显式使用 `@astrojs/markdown-remark` 的 `unified({ remarkPlugins, rehypePlugins })`；`plugins/index.ts` 是既有 Markdown/MDX 插件顺序的权威，不能依赖 Astro 7 默认的 Sätteri，否则宽度标记、阅读时间、标题锚点等不会按当前规则处理。其中 `rehype-raw` 必须先于处理原生 HTML 元素的阶段（否则手写 HTML 尚不是元素）；当前顺序为 `rehypeRaw` → `rehypeImageSources` → `rehypeMediaAssets`，不要求 raw 与媒体插件相邻。Astro 图片管线转 WebP、生成 `srcset`、注入宽高与懒加载；宽度标记由 `plugins/remark-image-width.ts` 转成 `width` 后交给管线，`scripts/verify-markdown-pipeline.mjs` 在构建产物上验接线。

**调用方**：Markdown 正文、`PostHero`、`ListItem`、`RenderPost`（生成 1200px 分享图）。文稿列表第一张封面用 `priority`（`eager` + `fetchpriority="high"`）；其余列表图、标签页未展示的图、友链头像保持懒加载。文章封面 `PostHero` 始终 `priority`。有封面文章先显示普通标题与简短阅读信息，再显示封面；封面中的重复标题使用段落，描述优先取 description、缺失取 subtitle，作者行仅展示头像、梧桐雨和日期。深浅主题都使用深色遮罩与白色封面文字；无封面文章直接展示独立标题及正文。

内容图片按源文件位置解析，`./` 与 `../` 都能进管线；推荐图片与文章同目录，上层共享图也可直接引用。宽度用 alt 的 `|w` 标记表达，让 `width` 同时决定 `srcset` 与 `sizes`，完整作者约定以[Astro 图片管线指南](./Astro图片管线指南.md)为准。

**作者显式像素宽度用 `|w` 标记，布局容器的响应式尺寸由 CSS 管理**：标记转成 `width` 参与 Astro 的 `srcset`／`sizes`，不能只用 CSS 代替作者限宽；gallery／figure 容器可以响应式收窄图片、保持宽高比，不因此改变标记语义或手写资源 URL。

管线产物地址带内容哈希（`/_astro/...`），不可手写；`public/` 只放站点级资源（favicon、avatar、PWA 图标、默认 OG 图、字体），其中 `public/_media/` 是 `astro-media-sync` 生成的派生产物、已进 `.gitignore`，同样不可手写。`pnpm build` 使用 `--force` 刷新内容集合缓存，修改插件后直接重新构建即可。完整约定见[Astro 图片管线指南](./Astro图片管线指南.md)。

### 4.9 图片布局与交互 seam

语法、默认值和失败契约以 [站点行为 SPEC](./站点行为%20SPEC.md) S8／S9 为准；作者示例见 [图片管线指南](./Astro图片管线指南.md)。以下描述当前实现及对应验证接口。

```text
Markdown 相对源图 + |w + gallery／figure
  → remarkDirective → remarkImageWidth → remarkMediaCard
  → remarkImageLayouts：验证结构／属性，输出布局与 image-view
      ├─ 可见图片节点：保留作者宽度
      └─ inert template 图片节点：原尺寸，不沿用缩略图宽度
  → rehypeRaw → 同模块 rehypeImageSources：使 template 内容可被 Astro 图片 visitor 访问
      仅 Astro 已认领的图设置单资源输出，不重复判定路径类型
  → rehypeMediaAssets：媒体引用改写与校验
  → 同一 Astro 图片管线：解析资源；可见图保留响应式，大图仅产出原尺寸单版本
  → Content
      ├─ 网页：prose.css 静态排版；image-interactions.ts 渐进增强
      └─ RSS：既有 rss-content.js sanitizer 去掉 template／样式／控件
               → 可见图片与全部文字按源顺序保留
```

| 义务／状态／资源 | Authority | Interface／seam 与调用方 | 验证接口 |
| --- | --- | --- | --- |
| 指令属性默认值与白名单、直接图片结构、不能嵌套、非法输入带位置失败 | `plugins/remark-image-layouts.ts` | MDAST + VFile → 布局节点；figure 的图后正文必须有可见文字，注释、br、空 HTML 或只有媒体的内容不算；widths 在此验证 px／fr、数量与列数匹配并输出 --image-gallery-columns，CSS 只消费已验证轨道；`plugins/index.ts` 固定在 `remarkMediaCard` 后调用，错误由 VFile 携带位置，不由视图再判断 | `test/remark-image-layouts.test.mjs` |

| 稿件落地（本地图片搬入文章目录、外链保持外链、按内容排版、生成卡片）与预览交接 | `blog-content-publisher-skill/SKILL.md` | 读文章正文判断是否需要预览（排版／卡片／媒体）；同 worktree dev 的 cwd、日志 Local 地址与文章 HTTP 成功后交付链接 | 作者操作核实；纯文字与普通单图不触发预览，代码块示例不触发，不增加正则检测脚本 |

HAST 中 template 的 children／content 共享图节点：Astro 从 children 原位改写属性，最终 raw pass 从 content 序列化，两侧均不替换节点。仅对 Astro 已认领的图设置单资源输出，未被认领的公网／public 图不携带内部优化属性。

浏览器只从 template 内已经解析的 img 取得原尺寸资源，打开 dialog 时才赋给展示图，不预加载。原生 dialog 提供模态及 Esc 基础行为，浏览器属主处理大图点击／遮罩／关闭按钮、焦点恢复与打开前滚动锁恢复；普通图本身获得可聚焦的 button 语义与 Enter／空格激活，不创建角落按钮。作者图片链接的点击不被劫持，链接外保留仅键盘焦点显露的大图入口。`prose.css` 在精细悬浮指针且无减少动态偏好时，轻微缩放图片并用原尺寸 frame 裁住边缘，移开复原；光标与灰白／暗色遮罩同样只由该样式属主管理。横滚相册的增强 wrapper 只承载图片边缘箭头与底部页码，少于两张时不生成 wrapper 或控件；当前索引由实际滚动位置决定，同时同步边界箭头、深色圆点及当前 frame 高度；圆点多于容器可见宽度时只滚动分页容器以露出当前点，不移动文章。ResizeObserver 监听 frame 的加载／尺寸变化，避免离屏竖图撑高横图区域；图片沿用原有限宽与比例，不增加另一套图片尺寸推断。组件 disconnect 用 AbortController 清理监听、断开 ResizeObserver，并释放 dialog 和页面资源，避免 ClientRouter 换页留下旧状态；不把焦点还给已断开的节点。页面滚动锁由既有 `misc.ts` 的 `lockScroll()` 统一处理滚动条补偿、保存先前样式，并返回绑定当时 body 的 release；图片交互只持有并释放它，backdrop 同样消费该接口，不维护第二套 overflow 策略；其 release 按 backdrop 元素持有，ClientRouter 取消旧页退出动画不会把旧 body 的 release 复用到新页。

取舍：所有相册图片静态存在，大图副本在构建期只生成单个原尺寸资源，不生成无法使用的响应式变体，也不在打开前下载；接受相册 HTML 和图资源随内容增长，不做虚拟化、自动播放、定时轮播或 `titleImage` 头图／文稿列表缩略图、头像放大；`:::card` 配图属于正文，仍可放大。不新增依赖、轮播库、第二个 Markdown 解析器、预览后台、preview manager 脚本或测试框架。RSS 不复刻页面布局，沿用 sanitizer 清洗后保留全部可见图文顺序。

测试直接映射最终义务：remark 单测负责合法／非法语法、widths 单位与数量、列数推导／匹配、默认值、同段多图、嵌套失败与源位置；`scripts/verify-image-layouts.mjs` 负责浏览器用户行为（无 JS 横滚、比例／固定列宽与窄屏回退、图片边缘箭头／底部深色圆点／长分页当前点可见、混合横竖图的当前区域高度、作者链接、原框内悬浮与减少动态、主题遮罩、dialog 四种关闭、键盘激活、恢复和清理）与 Astro 模板大图资源检查（实际原尺寸、无占位符、打开前无请求），不绑定视觉像素。`test/scroll-lock.test.mjs` 在共享属主接口验证补偿、先前样式恢复与不污染替换页的 body。RSS 顺序和清洗在既有正文转换／真实产物接口验证，不创建新 RSS 解析器；最终门禁仍包括 check／test／build／built 检查，dev 预览不替代构建。

## 7. 各页实现要点

### 首页 `/`

`BlogProfile` 无卡片背景：顶部是三列细时间进度，下一行头像／作者／INTJ 居中，RSS 居右；下方居中排列独立斜体名言「我与我周旋久，宁做我」和 20px 的六个社交图标，没有全站总数。社交入口由 `config.ts` 的 `AUTHOR_LINKS` 维护，名称保留给读屏器和悬停提示。窄屏作者组和 RSS 分别居中成行，社交一行，缩小横向间隔；时间进度标签和数字上下排列。`WritingHeatmap` 放在名片和近期笔墨之间。标题与近期笔墨左对齐，年份在标题右侧；日历按上海时区自然年、周一起始，只计已发布文章。每年摘要显示篇数、字数和有文章的天数。单篇格子是链接，多篇在脚本启用后从提示层进入。`RecentWriting` 在其下显示最近五篇已发布文稿，无卡片底色，标题大小接近正文。`RecentMedia` 再往下渲染 `src/content/interests/recent.md`，不另画边框，宽度跟首页版心走。正文标题和卡片仅使用共享 `prose.css`，没有首页专用覆盖；连续 `:::card` 按容器宽度自动分列，当前版心最多两列，宽屏单张保留空列、与双卡同宽，窄屏单列填满。Markdown 标题按原层级分段并保留锚点。该文件和 `intro.md` 一样排除出拾趣集合，不生成子页。首页不显示文章分页或个人侧栏。首页带 `?page=`、`?category=`、`?tag=` 的兼容书签在客户端转到 `/blogs/`。

### 文稿 `/blogs/`

这里的 hash 指 URL 片段，即 `#` 后的分类标识，不是哈希计算。访问 `/blogs/#tech` 只向服务器请求 `/blogs/`；脚本读取片段并执行筛选。分类配色的哈希计算是另一项独立机制。

首页、列表与归档直接读取 `data.category` 原值，不经过别名合并或固定分类映射。当前内容使用“技术”“思考”“日记”，日记仅含草稿、不进入顶部分类菜单；这些名称是内容现状，不是允许列表或固定入口。`ListView` 渲染全部文章节点并预置第一页导航；浏览器按 URL 精确筛选后分页，每页七篇。分类统一使用名称编码，如 `/blogs/#旅行`；旧 `#tech`、`#thought`、`#diary` 仅作为 URL 兼容别名，分别定位原值“技术”“思考”“日记”，不合并其他名称。兼容的 `?category=` 始终按原值精确匹配；任意合法分类 hash 优先于该 query，`categoryFromHash` 负责解码，英文原值 `tech`、`thought`、`diary` 用 `#category=tech` 等形式逃逸。畸形编码回退 query。`ListView` 将旧 query 转成等价 hash，保留其他 URL 参数。首屏内联脚本保守隐藏带非空 hash 的列表，最终分类判定由共享解析器完成，避免先显示未筛选文章。分页保留分类 hash 与标签，前进后退恢复状态；无 JS 时显示全部文章并说明筛选与分页不可用。列表项 `ListItem` 使用响应式图文布局。

### 拾趣 `/interests/`

拾趣各类有独立 Markdown 和静态 HTML，因此使用路径路由；博客分类复用全量文稿 HTML 并在客户端筛选，因此使用 hash。两者表达不同内容结构。

`src/content.config.ts` 扫描 `src/content/interests/` 顶层 `*.{md,mdx}`，排除 `intro.md`、`recent.md`；配图目录内的文件不自动成为分类。`interestSchema` 要求非空 `title`、`description` 和非负整数 `order`，不限定分类 ID 或数量，也没有 `draft` 过滤。`[id].astro` 的 `getStaticPaths()` 为集合条目生成静态子页，因此新增文件在重新构建后自动加入页面、入口与菜单。入口页按 `order` 升序展示分类链接，说明放在列表下方，只来自 `src/content/interests/intro.md`；首页近期书影游只读取 `recent.md`，二者都不生成子页或菜单项。

`InterestsView` 在 `/interests/<id>/` 只渲染该分类的内容，页面标题直接使用分类名。入口和顶部下拉菜单读取同一份集合元数据，内容无需 JS 即可阅读。`NavDropdown` 仅在 `INTEREST_ICONS` 自身含该 ID 且图标非空时输出图标节点，不读取原型链，无图标分类保留文字与链接、不留占位；`unocss.config.ts` 自动将映射值加入 safelist。分类增加后仍需检查菜单换行、窄屏边界与内部滚动。

入口与子页均使用点状背景。当前内容包括设备、动漫、电影、电视剧、游戏、书与 Kpop，分类列表和说明可以随内容调整。电影、电视剧、动漫、游戏、书的条目用 `:::card`，按容器宽度自动分列，当前版心最多两列。作者可按需填写 `score`，不由观看／游玩状态决定；未填写时不生成评分。封面放在对应分类子目录，仍走图片管线。

### 标签 `/tags/`

`TagFilter` 汇总标签。`ListView requireTags`：一篇不选则列表隐藏。排序（数量 / 名称）不得改已选集合。多选 AND，再点取消。防连点有 debounce。

排序控件以 `aria-pressed` 为唯一选中状态，CSS 伪元素在两个等宽按钮间滑动，选中底色为主题文字色、文字为背景色；未选中项悬停使用灰底。键盘焦点可见，减少动态效果时取消过渡；排序只重排现有标签，不新增一份选中状态或测量规则。

### 全站搜索

`SearchSwitch` 负责搜索、键盘选中、结果跳转与加载分页逻辑，`Backdrop` 负责关闭。搜索面板、输入框、结果、快捷键和遮罩的视觉样式统一放在静态加载的 `public/shell.css`，避免面板背景和阴影依赖未生效的工具类。面板使用主题的实色背景、边框和阴影；遮罩压暗并模糊页面，结果摘要与快捷键使用明确的次级文字颜色，选中结果有底色及左侧标记。手机端保留快捷键提示，长结果只在面板中间区域滚动；减少动画设置下关闭过渡。

Pagefind **按需加载**：面板打开时调 `window.ensurePagefind()`（打开与输入两处触发，带 memo），否则不拉 `pagefind.js` 与 worker；`pagefind-highlight.js` 只在带 `?search=` 的页面加载于 `astro:page-load`。没打开过搜索的访问因此零 Pagefind 请求。

面板声明了 `role="dialog" aria-modal="true"`，所以 Tab 在面板内循环（`SearchPanel.#handlePanelTab`），退出靠 Escape 或点击遮罩，两者都会把焦点还给搜索按钮。结果项是 `role="option" tabindex="-1"`，用方向键选择，并用 `aria-activedescendant` 把当前高亮项报给读屏器。

开发模式搜索仍使用模拟数据；真实 Pagefind 搜索需先 build，再在 preview 中验证。

### 归档 `/archives/`

`ArchiveView` ← `getGroupedPostsByYear`。点线 + 年份空心圆 + 文章小点。年份与日期位于时间线左侧，日期在列内右对齐并靠近时间线；日期、标记和标题首行共用 24px 高度。每篇文章的标签在标题下方自然换行，标题下划线跟文字走，不拉满格子。

`blog-browser.js` 的 `getBlogCategoryColors` 是分类配色的唯一属主：所有分类统一按原始名称计算稳定的 32 位哈希并映射到 HSL 色相（浅色主题 32% 饱和度／36% 亮度，深色 32%／72%），不设固定类别调色板、不依赖分类序号，因此其他分类增删不影响颜色。`ArchiveView` 只将两个生成的安全颜色写入 CSS 变量，`shell.css` 选择当前主题颜色并呈现徽标，宽度最多占标题行的 40%，长名称换行，保留文章标题的可用宽度。颜色可相近，名称仍是分类识别依据；改分类名会改变链接与颜色。

分类与 URL、预览数量、编码冲突、空集合和颜色规则由 `test/blog-browser.test.mjs` 验证；构建菜单检查核对当前已发布集合中的原值分类、计数及排序、每类最多四篇预览的已发布链接，并核对名称编码 hash 链接与归档徽标变量，验证数据到页面的接线。

### 项目 `/projects/`

页头由共享 `PageHeading` 展示「项目／我的项目与开源实践。」；`GroupView` ← `projects` JSON。`icon` 可选。分类字符串来自数据，组件不写死类名；`GroupView` 用无原型字典分组，`constructor`、`__proto__` 等名称不与内建属性冲突，每条项目保留一次。

### 关于 `/about/`

页头由共享 `PageHeading` 展示「关于／关于我，也关于这个博客。」；`AboutView` 只读取 `about/about.md`，无子页面按钮、隐藏面板或切换脚本。关于内容仅维护 `about.md`，设备与兴趣内容由拾趣集合提供。关于页不放背景。首页社交链接由 `AUTHOR_LINKS` 独立维护，关于正文不必重复社交链接。

### 友链 `/friends/`

`FriendsView` 按数据 `category` 分成「推荐」「双向」两组，宋体小标题配简短说明。「推荐」是单向收藏，「双向」是已交换友链；schema 限定这两个值，避免无效分组被静默漏掉。组内按 `order`／名称排序并展示卡片，底部由 `FriendsApplyPanel` 展示交换说明。920px 以上说明和参考格式各占一半并等高，更窄时上下排列；说明里的 PR 按钮靠底，模板代码横向滚动。交换友链标题使用普通无衬线字体、700 字重。规则是“先友后链”和“使用 https 协议”。

### 文章 `/blogs/[slug]/`

`RenderPost` + 常驻右侧 TOC。最大高度 `min(50vh, 28rem)`，水平位置在侧边留白中线基础上向外移 16px、中心比视口中线高 32px，超出内部滚动；窄屏使用浮动目录按钮。文章主标题独立渲染，封面作者头像 40px。

页脚由 `Footer.astro` 用宋体显示版权、Astro 与“萌ICP备20269668号”。作者名、Astro 和备案都是带下划线的链接：作者名指向站点首页，Astro 指向 `https://astro.build`，备案指向 `https://icp.gov.moe/?keyword=20269668` 并在新标签页打开。悬停或键盘焦点时链接变为强调色。窄屏纵向排列，备案入口不隐藏。

## 10. 校验

```bash
pnpm format
pnpm lint
pnpm check
pnpm test
pnpm build # astro build --force 刷新内容缓存，避免 Markdown 插件更新仍沿用旧输出

pnpm test:built-restructure # 页面结构、菜单、目录、友链与文章语义

node --test test/remark-image-layouts.test.mjs # 布局属主接口、非法输入与源位置
```

浏览器检查均在本次 worktree 执行并复用现有 Ego TaskSpace，不自行管理服务。先确认服务进程 cwd 与该 worktree 一致（例如 `lsof -a -p <pid> -d cwd`），再从服务日志取真实 Local 地址（含 base、末尾 `/`），替换 `__BASE_URL__`；不假定端口为 4322。例如：

```bash
sed -e 's/__TASK_SPACE_ID__/<id>/g' -e 's|__BASE_URL__|<Local 地址>|g' scripts/verify-nav-dropdown.mjs | ego-browser nodejs
```

同样替换后运行 `verify-home-content.mjs`、`verify-toc-navigation.mjs`、`verify-theme-refresh.mjs` 和 `verify-background-layering.mjs`，分别验证首页、目录、主题恢复及背景层级。`verify-image-layouts.mjs` 还须将 `__REPO_ROOT__` 替换为同一 worktree 绝对路径（可加 `-e "s|__REPO_ROOT__|$PWD|g"`）；它在该 dev 服务中创建并最终删除临时草稿与小型 SVG 夹具，不修改真实文章，检查浏览器用户行为与 Astro 模板大图资源，不绑定视觉像素。
