# YuBlog 架构与实现

给后续开发用。改文案和数据走内容 skill；改行为先看本文件的**权威**和 **seam**，再动对应模块。Astro 语法见 [Astro.md](./Astro.md)，SEO 见 [Canonical URL、Sitemap、RSS.md](./Canonical%20URL、Sitemap、RSS.md)。

本次首页、导航与拾趣重构的行为合同、视觉方案和验收记录见 [博客重构设计与实施计划](./博客重构设计与实施计划.md)。

本文用这些词：

- **模块**：有界面、有实现的一块（函数、文件、页面拼装都可以）。
- **界面**：调用方必须知道的全部事实：签名、不变量、错误、配置、性能。
- **实现**：模块里面的代码。
- **seam**：界面所在的位置；可以在这里换实现、而不改调用方。
- **权威**：某类事实只允许在一处定义。别处只能读，不能再发明一份。

## 1. 这是什么站

Astro 7 静态站。主路径是**读文章**：首页名片与近期笔墨、文稿列表、标签筛选、年份归档、文章详情。文稿、标签、归档、拾趣、项目、关于、友链共用同一套居中单栏布局与悬浮导航。黑白主题，配置集中在 `src/config.ts`。

线上：`https://www.wutongyu.site/`。

构建：`pnpm build` → `dist/`（不进 git）→ `postbuild` 跑 Pagefind。

## 2. 页面地图

| 路由 | 人看到的 | 入口 | 数据权威 |
| :--- | :--- | :--- | :--- |
| `/` | 作者介绍 + 近期五篇笔墨，无卡片背景 | `src/pages/index.astro` | 已发布 `blogs` |
| `/blogs/` | 完整文稿列表，七篇分页，`#tech`／`#thought`／`#diary` 分类 | `src/pages/blogs/index.astro` | `blogs` 集合 |

| `/tags/` | 标签芯片；多选 AND；未选不列出文章 | `src/pages/tags.astro` | 同上，标签从文章 frontmatter 汇总 |
| `/archives/` | 按年时间线 | `src/pages/archives.astro` | 同上，按 `pubDate` 分组 |
| `/projects/` | 分类网格 | `src/pages/projects.mdx` | `src/content/projects/data.json` |
| `/about/` | 作者介绍 | `src/pages/about.mdx` | `src/content/about/about.md` |
| `/friends/` | 友链卡片 + 申请模板 | `src/pages/friends.mdx` | `src/content/friends/data.json` |
| `/blogs/[slug]/` | 正文、右侧 TOC | `src/pages/blogs/[...slug].astro` | 单篇 `blogs` |
| `/rss.xml` | 订阅源 | `src/pages/rss.xml.js` | 已发布 `blogs` |

顶栏页面链接的权威是 `src/config.ts` 的 `UI.internalNavs`。右侧只留 `UI.socialLinks` 里的 GitHub 项目链接（本仓库），和搜索、主题排在一起，不再插 `hr`。个人社交不进 `socialLinks`，写在关于页默认栏 `src/content/about/about.md`：GitHub 指向个人主页（无仓库名），X、Instagram、Bilibili、小红书跟在同一句后面。`NavBar.astro` 负责导航滑块：Astro 确认接管任意站内链接时，先按链接目标路径解析其顶层按钮，再把滑块移向该按钮，旧正文继续显示。拾趣子页统一对应「拾趣」，文稿分类和最近文章统一对应「文稿」；同一父级内切换保持滑块原位。下拉链接的 offset 相对于面板，不能用来定位顶栏滑块。标签、归档、首页近期笔墨等正文入口即使位于顶栏之外，也在导航准备阶段更新文稿高亮，不能等到页面交换完成才补播。滑块的不透明底色需要标签同时换色，所以有两个属性：`aria-current` 始终表示用户真正所在的页面（给读屏器和「当前页」语义），`data-nav-current` 表示滑块画在哪个项上（给 `shell.css` 的配色），导航预览期间只有后者会先走。`astro:page-load` 也会由 window load 或上一次导航触发，因此只有 URL 已经追上目标时才清除预览，否则保留待导航状态。前进／后退也从 Astro 事件目标 URL 解析父级；after-swap 在新页面绘制前同步最终高亮，page-load 再做幂等核对。只有当前请求的取消信号可撤回预览，旧请求不能撤回更新的导航。返回首页收起滑块并清除动画起点，下次显示直接定位。字体就绪与缩放期间不打断待导航的目标。品牌在首页带 aria-current，粉色及轻微文字加厚不改变它的宽度。外链、新标签页与浏览器默认处理的点击不走预览。

背景：首页 / 文稿 / 标签 / 归档 `dot`，项目 `rose`，友链 `snow`，关于 / 拾趣关闭。权威是各页传给 `BaseLayout` 的 `bgType`。

`dot` / `snow` 是 canvas 动画（`src/components/backgrounds/`）：

- `prefers-reduced-motion: reduce` 时只画一帧静态背景，不启动 RAF 循环，并在系统设置变化时启停。
- `dot` 每帧按透明度分 6 档批量描边。布点规则在 `Dot.astro`：基础间距 15px；估算点数超过约 8000 时按面积放大间距。这是目标，不是硬上限，边缘补点后 1080p 约 8160、4K 约 8349。常规 1440×900 仍是 15px / 6076 点。

## 4. Seam：该从哪切开

### 4.1 内容 seam

界面：Content Collections + Zod。  
实现：磁盘上的 md / json。  
调用方：`getCollection` / `getEntry` / `src/utils/data.ts`。

加一种新内容（例如新的关于标签）走集合，不要在 `.astro` 里写死数组。`about` 已经按文件扩展；新标签加一个 md 即可。

### 4.2 列表数据 seam

界面：`getFilteredPosts`、`getSortedPosts`、`getBlogListItems`、`getGroupedPostsByYear`、`getBlogStats`、`getRecentBlogPosts`、`getPublishedBlogPosts`。
实现：草稿过滤、日期排序、渲染 `minutesRead`、按年 reduce。

首页、文稿、顶部分类预览、标签、归档、RSS、名片、近期笔墨都应穿过这里。测试也打这个界面（`test/blog-stats.test.mjs` 等）。

### 4.3 浏览器状态 seam

界面：`serializeBlogQuery` / 解析查询串（`blog-browser.js`）。  
实现：`category`、`tags[]`、`page`、每页 7 篇。

`ListView` 负责把 DOM 和这个状态接上。改每页数量时，除了 `blog-browser.js` 和测试，还须同步 `ListView.astro` 的首屏 CSS `nth-child(n + 8)`（CSS 选择器不能读取 JS 常量）；筛选的 AND/OR 规则只在 `blog-browser.js` 改，不要改五处点击处理。

页码窗口由 `getPageNumbers` 统一生成，包含省略号最多 6 项（上一页 / 下一页另计）：总页数 ≤6 时全部显示；>6 时，优先判断当前页 ≤4，显示 `1 2 3 4 … N`；否则当前页 ≥N−3 显示 `1 … N−3 N−2 N−1 N`；其余显示 `1 … p p+1 … N`。省略号不可点击，至少代表两页；首尾和当前页始终可见。中间窗口优先展示下一页，无法同时保留前后邻页时可用独立的上一页 / 下一页控件连续翻页。生成窗口的计算和输出大小不随总页数增长。

`ListView` 仍负责标记当前页、禁用首尾的上一页/下一页，以及在 0 或 1 页时隐藏分页；筛选、每页文章数、URL 和前进后退规则不变。分页渲染成一行胶囊条：两端是同一枚箭头（`‹` / `›`，用 `aria-label` 给出「上一页 / 下一页」），中间是页码窗口，当前页画成填充块。`>480px` 时单项 `2.25rem`；`≤480px` 时单项降到 `1.9rem`、列间距降到 `0.25rem`、页码间距归零，让「箭头 + 六项窗口」共 8 项在 320px 视口内仍保持一行而不横向溢出。分页视觉统一放在 `public/shell.css`，由文稿和标签页共用，组件里不再重复定义。页码边界和 1–50 页所有有效当前页组合由 `test/blog-browser.test.mjs` 验证。

### 4.4 壳层样式 seam

界面：`public/shell.css` 的 class（`header.nav-bar`、`.blog-profile`、`.archive-*`、`.nav-dropdown`、`[data-pagination]`）。
加载：`Head.astro` 里真正的 `<link rel="stylesheet">`。

**不变量**：硬刷新和 ClientRouter 看到同一份 CSS。Vite 只打包一份外部 CSS（`_astro/style.*.css`，由 `cssCodeSplit: false` 产生），另外每页还加载独立的 `/shell.css`；组件 `<style>` 在硬加载和交换页面后都还在——「Vite 注入的 `<style>` 交换时会消失」并不成立（dev 与构建产物都验过：从 `/about/` 用 ClientRouter 跳到 `/`，组件的作用域规则仍在且命中元素）。`shell.css` 单独存在的理由是壳层 chrome 只有一个属主，不是防丢；构建结束后才生成的标题字体子集引用也放在这份不经 Vite 解析的静态 CSS 中。顶栏、布局、归档、分页属于壳，放 `shell.css`；文章正文、友链卡片仍用组件样式；桌面目录（`#toc-sidebar`）的规则放在 `src/styles/main.css`（`main.css` 与 `shell.css` 一样是每页加载的全局样式表，同样受下一条约束）。同一选择器不得同时出现在全局样式表和组件 `<style>` 里，`test/css-ownership.test.mjs` 会拦。

KaTeX 样式（约占主 CSS 的四分之一）从本地 `katex` 包引入（`src/styles/markdown.css`），由 Vite 打包：不再依赖 jsDelivr，也不会和 `rehype-katex` 渲染用的版本错配。字体产物落 `/_astro/`，全站只有 1 篇带公式的文章会真的取字体，其他页面为零请求。

`--font-heading`（本地思源宋体 400 字重）用于页面大标题、文章顶部标题、作者名与近期笔墨；文稿列表标题、Markdown 内部 h1–h6、正文、导航和标签使用 Inter／系统无衬线字体。品牌为全中文「梧桐雨的博客」，使用 16px 思源宋体；归档年份与日期也使用思源宋体。`PageHeading` 是标签、拾趣（含子页）、项目、关于的共享页头：标题 28px 宋体 400 字重，说明 14px 普通字体；友链分组标题为 24px 宋体。

正文字体 Inter 和代码字体 DM Mono 也在本地：`public/fonts/Inter-latin.woff2`、`public/fonts/DMMono-latin.woff2`，由 `src/styles/main.css` 的 `@font-face` 引用。不要再接 Google Fonts 或 `presetWebFonts`。这两份只含拉丁字符，中文走字体栈后面的系统字体。保留的两种手写字体 `@font-face` 在 `public/shell.css` 中，优先引用构建结束后生成的 `*-title.woff2` 子集，再回退到完整字体；`plugins/astro-subset-title-fonts.ts` 在构建后检查每个子集引用和文件都存在。Vite 不会提前解析尚未生成的字体路径。开发服务器没有子集时会回退到同一次声明里的完整文件，那不是线上行为。

主题、搜索、回顶、遮罩的点击在脚本执行时就绑定，不等第一次 `window` `load`。`astro:page-load` 只负责换页后的新节点，并用元素上的 `dataset` 避免重复绑定。

`plugins/postcss-katex-woff2-only.ts` 挂在 `vite.css.postcss`，在 Vite 生成 CSS 产物**之前**把 KaTeX `@font-face` 里的 woff / ttf 源去掉（约省 800 KiB 产物）。因为发生在产物生成前，CSS 文件名的哈希仍然对应所服务的字节；不能改到构建后处理（那时文件名已经定下）。上游 KaTeX 若变结构，插件会报错而不是静默产出坏字体。

### 4.5 布局 seam

- `BaseLayout`：文档头、背景、悬浮导航、主槽、页脚。
- `BlogIndexLayout`：导航页面的居中单栏容器。
- `StandardLayout`：文章标题、正文与普通内容排版。

全站没有个人右侧栏；`BlogProfile` 只在首页出现，下面是 `RecentWriting`。导航页统一通过 `BlogIndexLayout` 限制宽度。文章详情使用 `StandardLayout`，TOC 独立放在正文外侧。

桌面导航由 `--site-nav-width: 620px` 独立限制，友链后留约一个工具按钮宽度的空白；内容独立使用 `--blog-shell-width: 620px`。导航变化不会改变内容宽度，小屏两排导航仍受响应式外边距 `--site-gutter` 约束。`--blog-prose-width` 引用版心宽度，标题、正文与返回链接对齐；`--blog-article-width: 680px` 用于桌面 TOC 侧边可用空间计算，独立于阅读列。小屏由可用视口宽度约束。文稿有图卡片保留原有响应式列比和图片垂直居中规则。

导航是一条有细边框、轻阴影和柔和当前态的居中悬浮条，品牌、页面入口、工具按钮分组。≥800px 为一排，更窄视口为品牌／工具和页面入口两排。用 `top` 与 opacity 隐藏，不在包含搜索面板的祖先上使用 transform 或 backdrop-filter，保证搜索弹窗仍相对于视口定位。

### 4.6 导航与首页 seam

`nav-scroll.js` 负责滚动方向与阈值：顶部 80px 内始终显示；同方向累计 18px 后下滑隐藏、上滑显示。`NavBar` 将其结果呈现到 `data-scroll-hidden`，每帧最多处理一次，菜单展开、键盘焦点或搜索打开时保持可见，跨页导航重置。无脚本时导航保持显示；减少动态效果时关闭过渡。

文稿菜单由 `NavDropdown` 保存当前预览分类，只在实际分类链接的 pointerenter／focusin 时切换，鼠标走过行间隙时保留选择；无脚本的 hover／focus 降级仅应用于未绑定脚本的菜单。浏览器回归脚本为 `scripts/verify-nav-dropdown.mjs`。

顶部菜单读取 `getPublishedBlogPosts`，由 `blog-browser.js` 的共享分类映射生成最多四篇预览。名片统计的计算在 `data.ts`；进度数字在 `progress-stats.js`；近期五篇在 `getRecentBlogPosts`（与列表筛选无关）。近期五篇仅在首页显示，使用 `RecentWriting` 的组件样式。

### 4.7 TOC seam

`FEATURES.toc` 决定开不开、标题层级、左右（不再有 `displayMode` 显示档位）。  
`TocSidebar` 负责高度（不超过 `min(50vh, 28rem)`）和内部滚动。
`DesktopAside` 在 1200px 及以上始终显示目录，无顶部开关；宽度为侧边可用空间与 208px 中的较小值，沿用侧边外间距，垂直居中。更窄视口继续使用 `MobileTocControl` 浮动入口，展开时通知共享目录逻辑将当前项滚入可视范围。

当前章节由 `src/utils/toc-active.js` 的 `pickActiveHeadingIndex()` 决定：激活线取标题的 `scrollMarginTop`，到页面底部时最后一个标题胜出。`Toc` 唯一维护 `--post-anchor-offset`：导航隐藏时 20px，显示时为导航顶部位置加实际高度再加 12px。点击前复用 `updateNavScroll()` 预测导航的显隐状态，原生锚点直接消费对应距离；滚动、导航显隐、缩放和字体加载后重新核对同一基准。保留正常 fragment 与历史记录行为，不补播第二次滚动；移动目录不再写入旧固定顶栏高度。正文标题保留透明度入场，但取消纵向位移，避免刚进入页面便点击目录时发生 10px 的落点漂移；无脚本时保留导航可见所需的静态距离。

桌面目录各级标题在收窄后的栏宽内完整换行；当前项超出内部滚动区域时，`Toc` 将它滚回可视范围。

### 4.8 图片 seam

**界面**：内容里的相对图片路径（`./<目录>/文件.png`）、frontmatter 的 `titleImage: image()`、alt 尾部的宽度标记 `|w480`。  
**实现**：`astro.config.ts` 显式使用 `@astrojs/markdown-remark` 的 `unified({ remarkPlugins, rehypePlugins })`；`plugins/index.ts` 是既有 Markdown/MDX 插件顺序的权威，不能依赖 Astro 7 默认的 Sätteri，否则宽度标记、阅读时间、标题锚点等不会按当前规则处理。Astro 图片管线转 WebP、生成 `srcset`、注入宽高与懒加载；宽度标记由 `plugins/remark-image-width.ts` 转成 `width` 后交给管线，`scripts/verify-markdown-pipeline.mjs` 在构建产物上验接线。

**调用方**：Markdown 正文、`PostHero`、`ListItem`、`RenderPost`（生成 1200px 分享图）。文稿列表第一张封面用 `priority`（`eager` + `fetchpriority="high"`）；其余列表图、标签页未展示的图、友链头像保持懒加载。文章封面 `PostHero` 始终 `priority`。有封面文章先显示普通标题与简短阅读信息，再显示封面；封面中的重复标题使用段落，描述优先取 description、缺失取 subtitle，作者行仅展示头像、梧桐雨和日期。深浅主题都使用深色遮罩与白色封面文字；无封面文章保持原标题结构。

两条硬规则（来自实测）：

1. **正文图片必须位于文章所在目录或其子目录内**，不能用 `../` 越级，否则构建报 `ImageNotFound`。封面（frontmatter）没有这个限制。
2. **正文宽度只能用宽度标记表达，不能用 CSS**：Markdown 图片的节点属性会被直接转发给 `getImage`，只有 `width` 会同时决定 `srcset` 与 `sizes`。

管线产物地址带内容哈希（`/_astro/...`），不可手写；`public/` 只放站点级资源（favicon、avatar、PWA 图标、默认 OG 图、字体）。改 remark / rehype 插件后要删 `node_modules/.astro/`，否则内容缓存会让构建输出旧 HTML。完整约定见[Astro 图片管线指南](./Astro图片管线指南.md)。

## 5. 运行链路

```text

        ↓

        ↓

        ↓

        ↓
layouts                      壳
        ↓
components/views             这一页怎么拼
```

`astro.config.ts` 里 `cssCodeSplit: false` 让 Vite 只输出一份打包 CSS（另有 `/shell.css`），`inlineStylesheets: 'never'` 保证打包 CSS 是外部文件而不是被内联进每个页面——这两条才是「组件样式在交换后仍在」的实际原因。要改回去，先重跑 §4.4 里那条从 `/about/` 交换到 `/` 的验证。

## 7. 各页实现要点

### 首页 `/`

`BlogProfile` 无卡片背景：顶部是三列细时间进度，下一行头像与作者居左、RSS 居右；下方居中排列独立名言「我与我周旋久，宁做我」、用中点分隔的一行写作统计、24px 的六个社交图标。社交入口由 `config.ts` 的 `AUTHOR_LINKS` 维护，名称保留给读屏器和悬停提示。窄屏保持作者／RSS 同行，统计和社交各一行，缩小横向间隔；时间进度标签和数字上下排列。`RecentWriting` 在其下显示最近五篇已发布文稿，无卡片底色，标题大小接近正文。首页不显示文章分页或个人侧栏。旧首页的 `?page=`、`?category=`、`?tag=` 书签客户端转到 `/blogs/`。

### 文稿 `/blogs/`

`ListView` 渲染全部文章节点并预置第一页导航；浏览器按 URL 筛选后分页，每页七篇。`#tech` 合并技术向与工具向，`#thought` 映射思考向，`#diary` 映射日记与日记向；旧 `?category=` 仍精确筛原 frontmatter。识别的新分类 hash 优先于旧 query。分页保留分类 hash 与标签，前进后退恢复状态；无 JS 时显示全部文章并说明筛选与分页不可用。列表项 `ListItem` 保留原图文比例。

### 拾趣 `/interests/`

`InterestsView` 在入口页按 `order` 展示七个分类链接；在 `/interests/<id>/` 只渲染该分类的内容，页面标题直接使用分类名。入口和顶部下拉菜单读取同一份集合元数据，内容无需 JS 即可阅读。设备继承原 Use；动漫包含国漫，电影包含动画电影，电视剧包含综艺，游戏、书与 Kpop 各自独立。原 Hobby 的图片资源和未提交的新条目一并迁入。
### 标签 `/tags/`

`TagFilter` 汇总标签。`ListView requireTags`：一篇不选则列表隐藏。排序（数量 / 名称）不得改已选集合。多选 AND，再点取消。防连点有 debounce。

排序控件使用 `aria-pressed` 作为唯一选中状态，CSS 伪元素在两个等宽按钮间滑动，选中底色混合 28% 主题文字色与页面背景，文字使用主题文字色，避免纯黑 / 纯白的强烈反色。未选中项悬浮底色为 18% 主题文字色，并增加内边框；选中项悬浮时进一步加深灰色。按下和键盘焦点各有反馈。无需额外保存排序状态或测量按钮，标签列表仍直接重排；减少动画设置下关闭过渡。

### 全站搜索

`SearchSwitch` 保留搜索、键盘选中、结果跳转与加载分页逻辑，`Backdrop` 负责关闭。搜索面板、输入框、结果、快捷键和遮罩的视觉样式统一放在静态加载的 `public/shell.css`，避免面板背景和阴影依赖未生效的工具类。面板使用主题的实色背景、边框和阴影；遮罩压暗并模糊页面，结果摘要与快捷键使用明确的次级文字颜色，选中结果有底色及左侧标记。手机端保留快捷键提示，长结果只在面板中间区域滚动；减少动画设置下关闭新增过渡。

Pagefind **按需加载**：面板打开时调 `window.ensurePagefind()`（打开与输入两处触发，带 memo），否则不拉 `pagefind.js` 与 worker；`pagefind-highlight.js` 只在带 `?search=` 的页面加载于 `astro:page-load`。没打开过搜索的访问因此零 Pagefind 请求。

面板声明了 `role="dialog" aria-modal="true"`，所以 Tab 在面板内循环（`SearchPanel.#handlePanelTab`），退出靠 Escape 或点击遮罩，两者都会把焦点还给搜索按钮。结果项是 `role="option" tabindex="-1"`，用方向键选择，并用 `aria-activedescendant` 把当前高亮项报给读屏器。

开发模式搜索仍使用模拟数据；真实 Pagefind 搜索需先 build，再在 preview 中验证。

### 归档 `/archives/`

`ArchiveView` ← `getGroupedPostsByYear`。点线 + 年份空心圆 + 文章小点。日期在原列中右对齐，靠近时间线，年份位置不变；日期、标记和标题首行共用 24px 高度。每篇文章的标签在标题下方自然换行，标题下划线跟文字走，不拉满格子。

### 项目 `/projects/`

页头由共享 `PageHeading` 展示「项目／我的项目与开源实践。」；`GroupView` ← `projects` JSON。`icon` 可选。分类字符串来自数据，组件不写死类名。

### 关于 `/about/`

页头由共享 `PageHeading` 展示「关于／关于我，也关于这个博客。」；`AboutView` 只读取 `about/about.md`，无子页面按钮、隐藏面板或切换脚本。设备与兴趣迁到拾趣；Soul 源文件保留但不展示。关于页不放背景。个人社交链接仍在 Markdown 中维护，图标尺寸由 `shell.css` 的 `.about-social__icon` 管理。

### 友链 `/friends/`

`FriendsView` 按数据 `category` 分成「推荐」「双向」两组，宋体小标题配简短说明。「推荐」是单向收藏，「双向」是已交换友链；schema 限定这两个值，避免无效分组被静默漏掉。组内保留原排序和卡片，底部保留 `FriendsApplyPanel`，交换友链标题同样使用宋体。

### 文章 `/blogs/[slug]/`

`RenderPost` + 常驻右侧 TOC。最高约页面 2/3，超出滚动；窄屏使用浮动目录按钮。文章主标题下无装饰短线，封面作者头像 40px。
