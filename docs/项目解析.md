# YuBlog 架构与实现

给后续开发用。改文案和数据走内容 skill；改行为先看本文件的**权威**和 **seam**，再动对应模块。Astro 语法见 [Astro.md](./Astro.md)，SEO 见 [Canonical URL、Sitemap、RSS.md](./Canonical%20URL、Sitemap、RSS.md)。

本文用这些词：

- **模块**：有界面、有实现的一块（函数、文件、页面拼装都可以）。
- **界面**：调用方必须知道的全部事实：签名、不变量、错误、配置、性能。
- **实现**：模块里面的代码。
- **seam**：界面所在的位置；可以在这里换实现、而不改调用方。
- **权威**：某类事实只允许在一处定义。别处只能读，不能再发明一份。

## 1. 这是什么站

Astro 5 静态站。主路径是**读文章**：首页列表、标签筛选、年份归档、文章详情。项目、关于、友链和前三者共用同一套索引壳（顶栏 + 主栏 + 右栏）。黑白主题，配置集中在 `src/config.ts`。

线上：`https://www.wutongyu.site/`。

构建：`pnpm build` → `dist/`（不进 git）→ `postbuild` 跑 Pagefind。

## 2. 页面地图

| 路由 | 人看到的 | 入口 | 数据权威 |
| :--- | :--- | :--- | :--- |
| `/` | 文章列表，七篇分页，可按分类筛 | `src/pages/index.mdx` | `blogs` 集合 |
| `/tags/` | 标签芯片；多选 AND；未选不列出文章 | `src/pages/tags.astro` | 同上，标签从文章 frontmatter 汇总 |
| `/archives/` | 按年时间线 | `src/pages/archives.astro` | 同上，按 `pubDate` 分组 |
| `/projects/` | 分类网格 | `src/pages/projects.mdx` | `src/content/projects/data.json` |
| `/about/` | 介绍 + Use / Hobby / Soul | `src/pages/about.mdx` | `src/content/about/*.md` |
| `/friends/` | 友链卡片 + 申请模板 | `src/pages/friends.mdx` | `src/content/friends/data.json` |
| `/blogs/[slug]/` | 正文、右侧 TOC | `src/pages/blogs/[...slug].astro` | 单篇 `blogs` |
| `/rss.xml` | 订阅源 | `src/pages/rss.xml.js` | 已发布 `blogs` |

顶栏文案和链接的权威是 `src/config.ts` 的 `UI.internalNavs` / `UI.socialLinks`，不是各个页面自己写死。`NavBar.astro` 负责导航滑块：Astro 确认接管顶栏链接时先把滑块移向目标，旧正文继续显示。滑块的不透明底色需要标签同时换色，所以有两个属性：`aria-current` 始终表示用户真正所在的页面（给读屏器和「当前页」语义），`data-nav-current` 表示滑块画在哪个项上（给 `shell.css` 的配色），导航预览期间只有后者会先走。`astro:page-load` 也会由 window load 或上一次导航触发，因此只有 URL 已经追上目标时才清除预览，否则保留待导航状态。导航取消时滑块回到当前页；字体就绪与缩放期间不打断待导航的目标。外链、新标签页与浏览器默认处理的点击不走预览。

背景：首页 / 标签 / 归档 `dot`，项目 `rose`，友链 `snow`，关于关闭。权威是各页传给 `BaseLayout` 的 `bgType`。

`dot` / `snow` 是 canvas 动画（`src/components/backgrounds/`）：

- `prefers-reduced-motion: reduce` 时只画一帧静态背景，不启动 RAF 循环，并在系统设置变化时启停。
- `dot` 每帧按透明度分 6 档批量描边。布点规则在 `Dot.astro`：基础间距 15px；估算点数超过约 8000 时按面积放大间距。这是目标，不是硬上限，边缘补点后 1080p 约 8160、4K 约 8349。常规 1440×900 仍是 15px / 6076 点。

## 4. Seam：该从哪切开

### 4.1 内容 seam

界面：Content Collections + Zod。  
实现：磁盘上的 md / json。  
调用方：`getCollection` / `getEntry` / `src/utils/data.ts`。

加一种新内容（例如新的关于标签）走集合，不要在 `.astro` 里写死数组。`about` 已经按文件扩展；新标签加一个 md 即可。

### 4.2 列表数据 seam

界面：`getFilteredPosts`、`getSortedPosts`、`getBlogListItems`、`getGroupedPostsByYear`、`getBlogStats`、`getRecentBlogPosts`。  
实现：草稿过滤、日期排序、渲染 `minutesRead`、按年 reduce。

首页、标签、归档、RSS、名片、近期文章都应穿过这里。测试也打这个界面（`test/blog-stats.test.mjs` 等）。

### 4.3 浏览器状态 seam

界面：`serializeBlogQuery` / 解析查询串（`blog-browser.js`）。  
实现：`category`、`tags[]`、`page`、每页 7 篇。

`ListView` 负责把 DOM 和这个状态接上。改每页数量时，除了 `blog-browser.js` 和测试，还须同步 `ListView.astro` 的首屏 CSS `nth-child(n + 8)`（CSS 选择器不能读取 JS 常量）；筛选的 AND/OR 规则只在 `blog-browser.js` 改，不要改五处点击处理。

页码窗口由 `getPageNumbers` 统一生成，包含省略号最多 6 项（上一页 / 下一页另计）：总页数 ≤6 时全部显示；>6 时，优先判断当前页 ≤4，显示 `1 2 3 4 … N`；否则当前页 ≥N−3 显示 `1 … N−3 N−2 N−1 N`；其余显示 `1 … p p+1 … N`。省略号不可点击，至少代表两页；首尾和当前页始终可见。中间窗口优先展示下一页，无法同时保留前后邻页时可用独立的上一页 / 下一页控件连续翻页。生成窗口的计算和输出大小不随总页数增长。

`ListView` 仍负责标记当前页、禁用首尾的上一页/下一页，以及在 0 或 1 页时隐藏分页；筛选、每页文章数、URL 和前进后退规则不变。分页渲染成一行胶囊条：两端是同一枚箭头（`‹` / `›`，用 `aria-label` 给出「上一页 / 下一页」），中间是页码窗口，当前页画成填充块。`>480px` 时单项 `2.25rem`；`≤480px` 时单项降到 `1.9rem`、列间距降到 `0.25rem`、页码间距归零，让「箭头 + 六项窗口」共 8 项在 320px 视口内仍保持一行而不横向溢出。分页视觉统一放在 `public/shell.css`，由首页和标签页共用，组件里不再重复定义。页码边界和 1–50 页所有有效当前页组合由 `test/blog-browser.test.mjs` 验证。

### 4.4 壳层样式 seam

界面：`public/shell.css` 的 class（`header.nav-bar`、`.blog-profile`、`.archive-*`、`.about-tabs`、`[data-pagination]`）。  
加载：`Head.astro` 里真正的 `<link rel="stylesheet">`。

**不变量**：硬刷新和 ClientRouter 看到同一份 CSS。Vite 只打包一份外部 CSS（`_astro/style.*.css`，由 `cssCodeSplit: false` 产生），另外每页还加载独立的 `/shell.css`；组件 `<style>` 在硬加载和交换页面后都还在——「Vite 注入的 `<style>` 交换时会消失」并不成立（dev 与构建产物都验过：从 `/about/` 用 ClientRouter 跳到 `/`，组件的作用域规则仍在且命中元素）。`shell.css` 单独存在的理由是壳层 chrome 只有一个属主，不是防丢。顶栏、右栏、归档、关于标签、分页属于壳，放 `shell.css`；文章正文、友链卡片仍用组件样式；桌面目录（`#toc-sidebar`）的规则放在 `src/styles/main.css`（`main.css` 与 `shell.css` 一样是每页加载的全局样式表，同样受下一条约束）。同一选择器不得同时出现在全局样式表和组件 `<style>` 里，`test/css-ownership.test.mjs` 会拦。

KaTeX 样式（约占主 CSS 的四分之一）从本地 `katex` 包引入（`src/styles/markdown.css`），由 Vite 打包：不再依赖 jsDelivr，也不会和 `rehype-katex` 渲染用的版本错配。字体产物落 `/_astro/`，全站只有 1 篇带公式的文章会真的取字体，其他页面为零请求。

`plugins/postcss-katex-woff2-only.ts` 挂在 `vite.css.postcss`，在 Vite 生成 CSS 产物**之前**把 KaTeX `@font-face` 里的 woff / ttf 源去掉（约省 800 KiB 产物）。因为发生在产物生成前，CSS 文件名的哈希仍然对应所服务的字节；不能改到构建后处理（那时文件名已经定下）。上游 KaTeX 若变结构，插件会报错而不是静默产出坏字体。

### 4.5 布局 seam

- `BaseLayout`：文档头、背景、顶栏、主槽、页脚。不负责两栏。
- `BlogIndexLayout`：主栏 + 右栏。索引页的唯一两栏拼装处。
- `StandardLayout`：文章详情。

`BlogIndexLayout` 在宽屏下监听右栏尺寸和页面滚动：右栏先随主栏正常滚动，右栏底部到达预留间距后转为固定定位，主栏继续滚动；右栏尺寸变化时重新计算边界。窄屏直接恢复单栏流式布局。锁定时布局写入 `--sidebar-left`、`--sidebar-width`、`--sidebar-bottom-gap` 和 `data-sidebar-locked`；`shell.css` 只消费这些做固定定位。`BLOG_SIDEBAR_BREAKPOINT` 在 `blog-sidebar.js`；CSS `@media` 读不到 JS，窄屏单栏和解锁必须抄同一数字并注明。文章详情使用 `StandardLayout`，没有博客右栏，只共享固定顶栏。

桌面 ≥1100px 的索引版心与全站顶栏共用根级 `--blog-shell-width: 904px`，索引主栏 648px、栏距 44px、右栏 212px；更窄视口保留 858px 上限与原单栏规则。文章标题、正文、返回链接与桌面 TOC 共用 `--blog-article-width`：保留默认 65ch、≥1280px 为 70ch 的原有阅读宽度，小屏由可用视口宽度约束。其他 `StandardLayout` 页面仍使用 `--blog-prose-width`。首页有图卡片在 ≥1100px 使用文字约 57.69% / 图片约 42.31%（15:11） 的列比，用户已接受图片放大后的自然增高。卡片 ≥768px 时图片使用 Grid 的 `align-self: center` 在内容行内自动垂直居中；≤767px 仍上下排列。版心与卡片列比的历史基线见 PR #75。

新的「和首页一样带右栏」的页面：套 `BlogIndexLayout`，不要复制侧栏 JSX。

### 4.6 右栏内部 seam

`BlogSidebar` 只装配三块：名片、近期文章、分类，并用 `data-blog-sidebar`、`data-sidebar-bottom-gap-source` 给布局当测量界面。顶栏高度走 `NavBar` 的 `data-site-header`。布局只读这些 data 契约，不读 `.blog-sidebar`、`header.nav-bar` 或近期文章内部 class。`blog-sidebar.js` 的锁定判定在顶栏高度或底部测量值缺失时返回 false；布局随即解锁并清理固定定位参数，不写入无效的 `nullpx`。这条规则由 `test:blog-sidebar` 覆盖。
名片统计的计算在 `data.ts`；进度数字在 `progress-stats.js`；近期五篇在 `getRecentBlogPosts`（**与主栏筛选无关**）。右栏 compact 近期文章的视觉在 `shell.css`。

### 4.7 TOC seam

`FEATURES.toc` 决定开不开、标题层级、左右（不再有 `displayMode` 显示档位）。  
`TocSidebar` 负责高度（约 `66vh`）和滚动。  
显示状态在 `DesktopAside`：点「目录」toggle `data-open`（触发器上是 `aria-expanded`），再点隐藏。关闭时用 `visibility` 隐藏，所以不会被 Tab 聚焦。不要把开关写进 `config.ts`（那是运行时 UI 状态，不是站点配置）。

当前章节由 `src/utils/toc-active.js` 的 `pickActiveHeadingIndex()` 决定（旧实现是 `IntersectionObserver`）：激活线取标题的 `scrollMarginTop`，到页面底部时最后一个标题胜出。

桌面目录各级标题在现有栏宽内完整换行；`TocSidebar` 的高度和滚动边界保持不变。

### 4.8 图片 seam

**界面**：内容里的相对图片路径（`./<目录>/文件.png`）、frontmatter 的 `titleImage: image()`、alt 尾部的宽度标记 `|w480`。  
**实现**：Astro 图片管线（转 WebP、生成 `srcset`、注入宽高、懒加载）；宽度标记由 `plugins/remark-image-width.ts` 转成 `width` 后交给管线。  
**调用方**：Markdown 正文、`PostHero`、`ListItem`、`RenderPost`（生成 1200px 分享图）。

两条硬规则（来自实测）：

1. **正文图片必须位于文章所在目录或其子目录内**，不能用 `../` 越级，否则构建报 `ImageNotFound`。封面（frontmatter）没有这个限制。
2. **正文宽度只能用宽度标记表达，不能用 CSS**：Markdown 图片的节点属性会被直接转发给 `getImage`，只有 `width` 会同时决定 `srcset` 与 `sizes`。

管线产物地址带内容哈希（`/_astro/...`），不可手写；`public/` 只放站点级资源（favicon、avatar、PWA 图标、默认 OG 图、字体）。改 remark / rehype 插件后要删 `node_modules/.astro/`，否则内容缓存会让构建输出旧 HTML。完整约定见[Astro 图片管线指南](./Astro图片管线指南.md)。

## 7. 各页实现要点

### 首页 `/`

`ListView` 渲染全部文章节点，并在首页 HTML 里预置第一页导航；浏览器接管后按查询串筛选和分页。无 JS 时显示全部文章，隐藏不生效的分页导航。选分类后出现「分类 / 名称 / 共 N 篇」。列表项 `ListItem`：桌面文字约 57.69% + 图约 42.31%（15:11），图来自 `titleImage`。

### 标签 `/tags/`

`TagFilter` 汇总标签。`ListView requireTags`：一篇不选则列表隐藏。排序（数量 / 名称）不得改已选集合。多选 AND，再点取消。防连点有 debounce。

排序控件使用 `aria-pressed` 作为唯一选中状态，CSS 伪元素在两个等宽按钮间滑动，选中底色混合 28% 主题文字色与页面背景，文字使用主题文字色，避免纯黑 / 纯白的强烈反色。未选中项悬浮底色为 18% 主题文字色，并增加内边框；选中项悬浮时进一步加深灰色。按下和键盘焦点各有反馈。无需额外保存排序状态或测量按钮，标签列表仍直接重排；减少动画设置下关闭过渡。

### 全站搜索

`SearchSwitch` 保留搜索、键盘选中、结果跳转与加载分页逻辑，`Backdrop` 负责关闭。搜索面板、输入框、结果、快捷键和遮罩的视觉样式统一放在静态加载的 `public/shell.css`，避免面板背景和阴影依赖未生效的工具类。面板使用主题的实色背景、边框和阴影；遮罩压暗并模糊页面，结果摘要与快捷键使用明确的次级文字颜色，选中结果有底色及左侧标记。手机端保留快捷键提示，长结果只在面板中间区域滚动；减少动画设置下关闭新增过渡。

Pagefind **按需加载**：面板打开时调 `window.ensurePagefind()`（打开与输入两处触发，带 memo），否则不拉 `pagefind.js` 与 worker；`pagefind-highlight.js` 只在带 `?search=` 的页面加载于 `astro:page-load`。没打开过搜索的访问因此零 Pagefind 请求。

面板声明了 `role="dialog" aria-modal="true"`，所以 Tab 在面板内循环（`SearchPanel.#handlePanelTab`），退出靠 Escape 或点击遮罩，两者都会把焦点还给搜索按钮。结果项是 `role="option" tabindex="-1"`，用方向键选择，并用 `aria-activedescendant` 把当前高亮项报给读屏器。

开发模式搜索仍使用模拟数据；真实 Pagefind 搜索需先 build，再在 preview 中验证。

### 归档 `/archives/`

`ArchiveView` ← `getGroupedPostsByYear`。点线 + 年份空心圆 + 文章小点。每篇文章的标签在标题下方自然换行，标题下划线跟文字走，不拉满格子。

### 项目 `/projects/`

`GroupView` ← `projects` JSON。`icon` 可选。分类字符串来自数据，组件不写死类名。

### 关于 `/about/`

`AboutView` 读 `about` 集合。按 `order` 排按钮，第一项默认选中。`tab: false` 不进按钮，显示在按钮下方。hash `#use` 可直达。关于页不要背景。

### 友链 `/friends/`

`FriendsView` 一张列表（不按 category 再分视觉大组，但仍有字段）。底部 `FriendsApplyPanel`：左说明、右 `friend.txt` 编辑器框。

### 文章 `/blogs/[slug]/`

`RenderPost` + 右侧 TOC。点「目录」显示／隐藏（关闭时靠 `visibility` 隐藏，不可聚焦）。最高约页面 2/3，超出滚动。
