# 站点行为 SPEC

本文是 YuBlog 的行为契约，规定页面应当怎样工作、视觉规则、不变量、模块边界和验收要求。用于确定需求与评审是否符合约定；具体实现链路由项目解析说明。源码、测试与本规范应保持一致；架构说明见 [项目解析](./项目解析.md)，发布变化见 [CHANGELOG](../CHANGELOG.md)，全文订阅规则见 [RSS SPEC](./RSS%20全文支持%20SPEC.md)。

## 1. 路由与使用场景

| 页面 | 路由 | 职责 |
| --- | --- | --- |
| 首页 | `/` | 时间进度、作者、RSS、名言、六个社交入口、写作热力、最近五篇文稿和近期书影游 |
| 文稿 | `/blogs/` | 全量文章列表、分类／标签筛选、每页七篇 |
| 分类 | `/blogs/#技术`、`#思考`、`#旅行`（名称经 URL 编码） | 同一文稿页的原值精确筛选状态，非独立静态页面；旧 `#tech`、`#thought`、`#diary` 仅作 URL 兼容别名 |
| 标签 | `/tags/` | 标签目录、排序、多选 AND 筛选；无选择时不显示文章列表 |
| 归档 | `/archives/` | 单条时间线，按年组织，分类徽标辅助识别 |
| 拾趣 | `/interests/` | 按内容集合和 `order` 自动生成分类入口 |
| 拾趣子页 | `/interests/<id>/` | 对应分类文件的内容，标题不带“拾趣-”前缀 |
| 项目 | `/projects/` | 页头和按 JSON 分类的项目卡片 |
| 关于 | `/about/` | 页头及作者介绍；仅维护 `about.md`，无子页切换 |
| 友链 | `/friends/` | 推荐、双向两组卡片及交换说明 |
| 正文 | `/blogs/<slug>/` | 独立标题、可选封面、正文和目录 |
| 订阅 | `/rss.xml` | 开发和生产均只含已发布文稿的完整正文，不包含页面壳或交互 |

## 2. 用户场景与产品规则

### S1：首页认识作者，再进入文稿

首页顶部先显示三列细时间进度。头像、梧桐雨、INTJ 作为一组水平居中，桌面 RSS 在同一行右侧；600px 及以下 RSS 单独居中一行，避免挤压作者。下方依次居中排列斜体的「我与我周旋久，宁做我」和六个社交图标，不再显示全站文章、字数或写作天数。社交入口保留名称供读屏和悬停提示，身份由 `AUTHOR_LINKS` 维护，包含 GitHub、X、Instagram、Bilibili、小红书与邮箱。

名片与近期笔墨之间是写作热力。标题「写作热力」与「近期笔墨」左对齐，年份在同一行右侧；只有一年时只显示年份。格子按上海时区的自然年排列，周一为一周之始，覆盖 1 月至 12 月。年外补齐日不着色、不计数。每年摘要按同一上海自然年显示篇数、字数和有文章的天数；字数是该年已发布文章的可读字数，满一万用「万」，缺字数时构建失败，不显示 0。只统计已发布文章，同一天多篇合并；强度为无文章、1 篇、2 篇、3 篇、4 篇及以上。颜色用强调色混入背景，浅色白粉、深色黑粉。默认选中当前年；当前年早于第一篇时选最近有文章的年份，不补博客开始前的空年。没有已发布文章时不渲染。单篇格子链到文章或重定向地址；多篇格子在启用脚本后展开各篇链接。空日不进入 Tab 顺序。年份切换不依赖脚本。提示层在视口内限高并可滚动，不限制当天文章数量；键盘焦点留在提示层时不因指针离开而关闭，提示层内部滚动不关闭；Escape 返回触发格子，页面交换清理定时器和监听。窄屏保持格子尺寸，在版心内横向滚动；放得下时格子组居中。

近期笔墨下方显示近期书影游，内容只来自 `src/content/interests/recent.md`，不生成拾趣子页或菜单项。无外框或专用内容宽度，继承首页版心；标题层级、锚点和卡片均使用共享 Markdown 样式。连续卡片根据容器宽度自动分列，在当前版心最多两列；标题分开各组，宽屏单张保留空列、与双卡同宽，窄屏填满一行。

首页最近五篇只包含已发布文章；每项有标题、分类与日期，标题在悬停和键盘焦点时出现下划线。全部文稿进入 `/blogs/`。首页带 `?page=`、`?category=`、`?tag=` 的兼容书签在启用脚本时解析为文稿页地址，保留参数和 hash；无脚本时首页仍可阅读。部署必须保留 `/blogs/` 的独立列表页面，不将 `/blogs` 或 `/blogs/` 重定向回首页；分类 hash 随同文稿 URL 保留，Vercel 使用 Astro 构建路由。

### S2：分类、标签和分页

博客分类以 frontmatter 的 `category` 原值为准，不合并任何别名，不归到兜底类别。首页、列表与归档直接读取 `data.category`，菜单也按原值展示、计数与精确筛选。当前内容的分类名为“技术”“思考”“日记”；已发布菜单为技术 40 篇、思考 1 篇，日记仅含草稿而不显示。这是当前内容示例，名称与篇数不是业务常量。

重新构建后，文稿菜单按已发布文章的原始分类生成入口，按篇数降序，同数按名称的 `zh-Hans-CN` 排序；不保留固定分组或空分类。分类使用 `/blogs/#旅行` 这样的名称编码 URL 片段（hash），旧 `?category=` 始终按原值精确筛选。分类 hash 及兼容 query 均可与标签、分页组合；畸形编码忽略 hash 后按 query 处理，不抛出异常。启用脚本后旧 query 规范为等价片段地址，保留标签、页码及其他参数。旧 `#tech`、`#thought`、`#diary` 仅作为 URL 兼容别名，分别定位原值“技术”“思考”“日记”，不合并“技术向”等名称；英文原值 `tech`、`thought`、`diary` 使用 `#category=tech` 等形式逃逸，仍为精确筛选。

文稿和标签筛选结果的文章标题使用宋体加粗（700），共用 `ListItem`；文稿列表标题字号为 18px，描述与元信息使用普通字体。文稿先对全量数据筛选，再分页，每页七篇。类别 hash 优先于兼容的 `?category=`；重复标签归一化、多选为 AND。修改筛选回第一页，分页保留筛选，越界页回到有效页，前进／后退恢复 URL 状态。首屏不先展示不匹配的第一页；禁用脚本时文稿展示全量文章及说明，标签页保留标签目录和启用脚本提示。

文章分类和搜索状态以当前 frontmatter 为准，不要求保留具体文章或占位内容。`search: false` 只控制搜索；未标为草稿的文章仍进入生产列表、归档和 RSS。

### S3：顶栏和下拉菜单

品牌“梧桐雨の博客”是首页入口；其余按钮为文稿、标签、归档、拾趣、项目、关于、更多，右侧保留本仓库 GitHub、搜索和主题开关。顶栏文字统一使用宋体。品牌为桌面 16px、601–799px 为 14.72px、600px 及以下为 14.4px，行高 1，容器与菜单保持中心对齐。首页品牌为粉色并轻微加厚，字宽不因选中而变化；其他当前项浅色黑底白字、深色白底黑字，未选中项悬停使用灰底。

文章及文稿分类属于文稿，拾趣子页属于拾趣。导航配置的尾斜杠不改变菜单或父级选中；服务端与客户端从 `nav-path.js` 读取同一规则，支持站点 base。滑块只使用顶层按钮坐标，同一父级内切换保持原位；文章入口无论来自标签、归档、首页、列表或菜单，都在导航准备阶段定位文稿。页面交换前后不重建滑块，不从零位置补播。最新导航目标拥有预览，旧请求取消不得撤回新目标；导航失败或被取消时恢复已加载页面的状态。`aria-current` 描述已加载页面，目标预览使用独立属性。

顶部文稿分类菜单只读取 `getPublishedBlogPosts` 集合：`draft` 不参与分类入口、计数或最近文章，这是明确的设计边界；仅含草稿的分类不出现，已发布集合为空时类别为空，仅保留“查看全部文稿”链接。开发网页列表与正文的草稿预览不属于此边界，行为不变。菜单左列按篇数降序、同数按名称的 `zh-Hans-CN` 排序，固定间距自上而下排列，不随右列拉高；右列最多四篇当前类别的最近已发布文章，保持共享发布日期顺序不变。面板高度取左右列较高者；分类较多时面板在视口内滚动，长名称换行；穿过行间空隙或右侧沟槽保留当前类别，不回退第一项。文章标题悬停／焦点有下划线，底部查看全部文稿行保持紧凑。拾趣菜单读取集合元数据，新分类随 Markdown 自动加入；标题、说明和顺序来自内容，图标按 `INTEREST_ICONS` 配置显示，未配置时显示纯文字、不留图标占位。拾趣和更多下拉框最大宽度 200px，并受导航容器宽度限制。更多菜单读取 `config.ts` 的 `MORE_LINKS`，友链指向 `/friends/`，友链页选中更多；相册指向独立部署的 `https://photos.wutongyu.site/`，显示 ↗，以新标签页打开并带 `noopener noreferrer`。

桌面 hover 或键盘焦点展开，触屏首次点名称展开、再次点进入入口页；ArrowDown／空格进入菜单，Enter 正常导航，Escape（包括仅鼠标悬停、焦点在菜单外时）和外部点击关闭。无脚本仍可通过 hover／focus 使用链接。

顶部 80px 内导航保持可见；同方向累计滚动 18px 后下滑隐藏、上滑显示。键盘焦点、打开的菜单或搜索会保持导航可见；页面切换恢复可见。减少动态效果偏好下关闭相关过渡。

### S4：拾趣和关于

拾趣入口与全部分类子页均使用点状背景。分类来自 `src/content/interests/` 顶层的 `.md` / `.mdx` 文件，排除 `intro.md` 和 `recent.md`，不限定分类 ID 或数量。

每个分类必须提供非空 `title`、`description` 和非负整数 `order`；入口与菜单按 `order` 升序展示，子页路径为 `/interests/<文件名去掉扩展名>/`。新增分类重新构建后自动生成页面、入口和菜单，无需修改路由或导航数组。图标唯一配置为 `src/config.ts` 的 `INTEREST_ICONS`，键为分类 ID，未配置时菜单只显示文字，不渲染图标容器或占位；图标值自动加入 UnoCSS safelist。拾趣没有博客的 `draft` 过滤，新增文件随下一次构建发布。

入口列表下方的说明只来自 `intro.md`，首页近期书影游只来自 `recent.md`，二者不生成分类子页或菜单项。当前分类包括设备、动漫、电影、电视剧、游戏、书、Kpop；这是内容现状，不是允许列表。各分类说明以内容元数据为准。电影、电视剧、动漫、游戏、书的条目使用 `:::card`，按容器宽度自动分列，当前版心最多两列。评分由作者按需填写，与观看／游玩状态无关；未填写时不生成评分。关于页只渲染 `about.md`，没有子页切换。

博客、拾趣、首页近期书影游与关于正文在 `prose.css` 共用标题字号和间距：h1 为 34px、h2 为 25.6px、h3 为 19px、h4–h6 为 16px（根字号 16px 时）。Markdown 的一至六个 `#` 按原样生成 h1–h6，不将文中最高级标题提升为 h1；标题旁单个 `#` 是 `rehype-autolink-headings` 添加的锚点链接，与层级无关。页面顶部的宋体标题独立渲染，不属于正文 Markdown。

### S5：归档和友链

归档按共享发布日期顺序排成一条时间线，年份为宋体 22px，日期为宋体，文章标题为宋体常规字重（400）、字号 14.72px；日期列右对齐并靠近时间线，年份在同一列展示。日期、标记与标题首行共用 24px 行高。所有分类的小点均为灰色，悬停／焦点均为粉色短竖线；标题右侧的圆角徽标包含分类文字，不能仅靠颜色区分。所有分类统一依据原始名称的稳定 hash 获得深浅主题配色，不设固定类别调色板；分类增删或文章排序不改变已有分类颜色。允许不同分类颜色相近，不保证颜色唯一。长分类徽标限制宽度并换行，不挤出手机页面。

友链 category 仅允许“推荐”或“双向”，每条友链的类别以当前数据为准；不设必须保留或禁止添加的站点名单。组内按 `order`／名称排序，两组用较小宋体标题及说明分隔，“交换友链”使用普通无衬线字体加粗（700）。申请区在 920px 以上左右等宽并等高，更窄时上下排列；规则为“先友后链”和“使用 https 协议”。卡片悬停／焦点加强边框和名称颜色，不整卡变灰或让头像发光；深浅主题可读，窄屏改为单列。

### S6：有封面和无封面文章

文章始终保留一个独立宋体 h1 及日期／阅读时长／标签信息。有封面时在其下渲染图片卡片：重复标题用段落，描述取 `description`、缺失时取 `subtitle`，作者行只含 40px 头像、梧桐雨与日期。封面白字和深色渐变遮罩适配两种主题。无封面时保持标题和正文结构，不构造假封面。

桌面 1200px 及以上目录常驻、无顶部 TOC 按钮；小屏保留浮动目录入口。目录在正文边缘和视口外边距之间的留白中线基础上向外移 16px，最大宽度 208px，宽度为侧边留白减 48px 与该上限中的较小值，靠正文一侧至少保留 40px，外侧至少保留 8px（另有视口外边距）；中心比视口中线高 32px；高度不超过 `min(50vh, 28rem)`，长目录在内部滚动，当前项移入可视范围。

目录点击与章节高亮共用阅读边缘：导航隐藏为 20px，显示为其顶部位置、实际高度再加 12px。点击前从共享模块维护的实际累计滚动状态预测显隐（预测不修改状态），让原生 fragment 滚动直接使用目标距离，不进行第二次补滚。滚动、字体／图片布局变化、缩放和导航显隐重新同步；到页面真正底部最后章节胜出。保留正常 URL hash 和历史返回语义；离开文章后清理监听、观察器及临时定位变量。无脚本时保留可见导航所需的静态间距。

### S7：文章与 RSS 共用内容管线

RSS endpoint 只渲染集合 `Content`，经静态 HTML 转换输出 `content:encoded`；摘要共存，订阅地址、GUID、发布日期与 redirect 语义按 RSS 契约生成。封面布局、头像行、导航、目录、主题 CSS／JS 不进入源；正文图片仍来自 Astro 解析的资源并变成站外可访问 URL。

不抓取 redirect 目标、不下载远程媒体，不用第二个 Markdown 解析器。开发和生产 RSS 均只读取已发布文章、排除草稿；任一文章渲染或转换失败使本次生成失败，不静默漏文或退回摘要。完整规范见 [RSS 全文支持 SPEC](./RSS%20全文支持%20SPEC.md)。

## 3. 视觉不变量

| 对象 | 规则与属主 |
| --- | --- |
| 内容与导航宽度 | `main.css` 配置 `--blog-shell-width`，`--site-nav-width` 引用它，使顶栏与正文宽度一致，更多右侧保留剩余空白。版心目标 660px，同时受 `100vw - 两侧外边距` 限制；1200px 及以上再减去 32rem，避免占用目录的 208px。页面和目录只读这个变量，不另写宽度 |
| 文稿列表封面列 | `ListItem.astro` 固定有图 250px、无图 222px。版心宽度变化只进入左侧文字，不在 `main.css` 再写一份列宽 |
| 页面顶部间距 | 所有页面共用 `shell.css` 的 `.site-main`：桌面顶部内边距 104px，799px 及以下 136px；可见顶栏下至内容的留白约 40px／36px |
| 导航 | `shell.css` 管理外框 4px、按钮／滑块 2px 圆角，紧凑一行，窄屏两排；更多右侧保留剩余空白 |
| 字体 | `--font-heading` 为本地思源宋体 400；页面主标题、文章顶部标题、作者、写作热力、近期笔墨、归档时间、页脚用它；导航文字用宋体；文稿列表文章标题用宋体加粗（700），归档文章标题用宋体常规字重（400）；Markdown 内部标题、正文和标签用 Inter／系统无衬线；代码用 DM Mono |
| 统一页头 | `PageHeading` 管理标签、拾趣及子页、项目、关于：28px 宋体标题、14px 普通字体说明；项目“我的项目与开源实践。”、关于“关于我，也关于这个博客。” |
| 首页 | 无卡片底，作者 28px（窄屏 22px），名言 17px 斜体，社交图标 20px；进度是辅助信息。写作热力标题 20px 宋体，与近期笔墨左对齐，年份在标题右侧；每年摘要含篇数、字数和天数。三块首页标题共用 `shell.css` 的 `.home-section-header`。格子颜色只由 `--accent` 混入 `--c-bg` |
| 友链页头 | 推荐／双向 24px 宋体，小于主要页面标题；交换说明标题使用普通无衬线字体加粗（700） |
| 图片 | 封面／正文图片由 Astro 生成变体，分享图 1200px；`public/` 只放站点资源，不手写内容图片构建 URL |

## 5. 失败、并发和资源语义

- `:::card` 的评分可省略；提供时必须是 0–5 的半星步进，非法评分和嵌套卡片构建失败，不改写分数。评分为真实文本，读屏与 RSS 不依赖星星 CSS；危险标题链接降级为纯文本。
- 静态内容在构建时验证。缺少作者介绍或无效 schema 明确报错；无文章／无匹配结果展示空状态。未知博客分类保留，非法友链类别由 schema 拒绝，不静默丢条目。写作热力遇到非法日期在构建时抛错；没有已发布文章时不渲染，不补第一篇文章之前的空年。
- 导航 pending 状态由对应 AbortSignal 拥有；后发目标替代先发目标，过期取消不能回退最新预览；只有 pathname 追上 pending 目标才完成预览，已排队的旧交换不能冒充另一个新目标完成。页面加载后的实际路径最终决定选中父级。
- 分类入口数随已发布分类数增长，菜单受视口高度约束并可滚动；改分类名会改变名称 hash 与自动颜色，不提供独立的分类改名迁移服务。
- 菜单预览每类最多四篇，首页最多五篇；文稿每页七篇，但静态 HTML 仍包含全量已过滤文章以支持无脚本回退，分页不按页发起网络加载。
- 导航更新用 rAF 合并；时间进度每 30 秒更新，页面交换前清除旧定时器。TOC 监听／观察器在连接时建立、断开时清理，字体完成回调只处理仍连接的元素。
- RSS逐篇处理，无部分 feed、无持久恢复状态；不新增文章数量或未来日期过滤上限。图片和字体由构建管线管理，失败构建不能作为成功产物发布。
- 复制友链模板失败给出“复制失败”反馈；无 JS 时模板仍可选取复制。搜索只按需加载现有 Pagefind；索引范围由搜索配置控制。

## 6. 支持范围和限制

- 文章 slug、域名和 base 决定永久地址；没有独立的文章改名或换域名 ID 服务。
- RSS 使用基础 HTML 和公式源码，不保证与网站或不同阅读器的像素样式一致。
- 新增顶栏项或拾趣分类需验证导航宽度、换行和响应式布局；下拉菜单受视口高度约束并可滚动，自动收录不意味着任意数量或长度都保证布局可用。
- 开发网页列表和正文可预览草稿；生产不可含草稿。首页摘要、写作热力、顶部分类菜单和开发／生产 RSS 只使用已发布集合；草稿不参与菜单入口、计数或最近文章，不保留仅含草稿的分类或空已发布集合的分类入口。
- `search: false` 与 RSS 范围独立，禁用搜索不等于不发布。博客文章是否下线由删除或草稿状态决定；拾趣没有草稿开关，移除分类文件后重新构建才移除对应子页、入口和菜单项。
- 目录最后的短章节可能无法滚到激活线，页面底部规则负责选中它；历史返回恢复浏览位置，不强迫 hash 标题重新对齐。

## 7. 验收入口

测试保护功能正确性、内容完整性、安全和可用性。算法与边界测试使用固定夹具；构建检查从当前配置、内容及产物推导预期，不把个人账号、文章标题、友链名单、兴趣分类数量、观看状态或具体 CSS 写法另设为不可修改规则。视觉调整通过实际可读性、视口边界和交互效果验证，不用调色板或像素值快照阻拦正常调整。

1. `pnpm test`、`pnpm check`、`pnpm lint`、`pnpm format`、`pnpm build`。
2. 构建后 `pnpm test:built-restructure`、`pnpm test:built-pagination`、`pnpm test:built-markdown`：集合范围、页面结构、拾趣自动分类与可选图标、友链分组、目录、封面语义、图片／RSS资源。
3. 在现有 Ego TaskSpace 中运行 `sed 's/__TASK_SPACE_ID__/<id>/g' scripts/verify-nav-dropdown.mjs | ego-browser nodejs` 、`verify-home-content.mjs` 和同样的 `verify-toc-navigation.mjs`；脚本不创建或结束 TaskSpace。
4. 深浅主题、1440／390／320px检查：首页作者中心、进度顺序、页头一致、归档日期对齐、卡片、点状背景、目录在右侧留白中线基础上向外移且上移、无横向溢出。目录另检查1200px阈值和不同视口高度。

验收记录注明实际环境与检查范围；本地结果不替代对应提交的 GitHub CI，浏览器测试不替代真实阅读器兼容性检查。
